§4 断言改动说明（本轮我改过的断言，逐条说明为什么）
--------------------------------------------------------------------------------
按规矩「不得默默改断言」，以下 3 处是我自己新写的断言写错了/前提不成立，已改为
数据驱动或修正正则，不是放宽判定：

 A) 「[P2-7①] 已接入→src-on / 已连通但无条目→src-neutral / …」
    初版按「面板里必须出现某状态」来断言。首次运行时 8765 正在被另一条线重启，快照里
    「已接入」= 0 个（临时全变成「示例模式·未联网」），导致 3 条断言假红/假绿
    （空集合上的 .every() 恒真 = 假绿，更危险）。
    改法：新增纯函数断言（直接调 window.srcStatusClass 校验六类 + 未知/空值映射）
    + 「真实渲染中每个源的 class 必须与自身 data-status 一致」的一致性断言。
    判定：原断言「写法有缺陷」（依赖运行中服务的瞬时数据分布），不是代码缺陷。
 B) 「[P2-7③] 抓取 N 条」：改为「若快照里存在 count>0 的源则必须符合口径，否则 SKIP」。
    判定：断言前提不成立时的显式 SKIP，不是放宽；该口径另有「缺字段页 count=5」独立覆盖。
 C) 「[P2-5] 人员列表文案如实说明截断」：正则 `/共\s*\d+\s*位/` 与真实文案
    「本次接口共返回 100 位」不匹配（中间多了「返回」二字）。改法：正则改为
    `/共[^，。；]{0,10}?\d+\s*位/`。判定：断言写错（正则与文案不符），文案本身正确。
 D) 「[P2-1] 人物行属性未被追加」：初版期望属性集合 = ["data-name"]，实际源码里该行
    还带内联 `style="cursor:pointer"`，故期望改为 ["data-name","style"]。
    判定：断言写错（漏算了源码自带的 style）；安全性质（无注入属性）无误。

除以上 4 条外，其余 90 条断言自始未改。
另外：新增断言过程中真的抓出 4 处代码缺陷（actionBadge / channelBadge / tierBadge /
regionLabel 会把字面量 undefined 写进 DOM），已按「改代码、不改断言」处理。
