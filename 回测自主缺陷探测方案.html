回测自主缺陷探测方案

股票论坛可视化查看器 · 质量保障（QA）体系升级 · 2026-10-08

一、一句话结论

当前 10 轮"回测/验证"全 PASS、却靠人工发现 bug，根因不是跑得少，而是这套验证从设计上只证明"系统能跑、能渲染"，从不证明"算得对"。根治 = 引入真值对照 + 领域对抗探针 + 故障注入自检 + 缺陷驱动回归，把验证从"管道冒烟"升级为"缺陷探测"。

二、现状证据：测试只验"存在/结构"，不验"正确"

验证脚本实际断言类型为什么抓不到 bug
verify_backend.py
（后端）		 存在性 / 类型 / 诚实报错二选一。B7 回测仅断言 n==2 and win_rate is not None（第 58-61 行） 一个偷偷前视、成本算错、胜率虚高的回测照样 PASS——从不验证数字是否对、是否离谱
verify_prediction.cjs
（前端）		 items.length===20、core===10、元素存在、控制台零报错（第 60-64、113-118 行） 从不验证这 20 只票真符合筛选逻辑，也不验证日期/asof——刚修的"9-30 卡死"这类 bug 永远抓不到（它只查 has_data===true）
verify_e2e.js
verify_screener_enh*.cjs		 按钮存在、面板可见、CSV 有内容、零 JS 错误 历史实锤：verify_screener_enh.cjs 基于错误假设（测了根本不存在的列）报"10/10 PASS"，实为假通过——测试脚本自己就是错的

结论：这是结构性 / 管道冒烟测试，不是正确性 / 缺陷探测测试。缺陷只要在"能跑通、字段在、不报错"的壳子里，全部隐形。

三、检测失效的 8 类根因（方案要覆盖的面）

#根因说明
1无真值对照（Oracle 缺失）没有"已知正确答案"去比对，回测数字无法被判对错，只能人眼扫
2只断言结构、不断言正确上一节证据，占大头
3无故障注入 / 变异测试从没"故意注入已知 bug、确认测试会 FAIL"。测试若永远 PASS，可能是它压根没在查任何东西——最致命的元缺陷
4测试与代码同源（确认偏误）写回测与写测试同一视角，易写成"断言 == 代码实际产出"（回归锁死）而非"应该产出"
5无领域特异探针回测致命缺陷族（前视 / 幸存者 / 复权漂移 / 过拟合 / 零成本虚高 / T+1·涨跌停·流动性 / 数据断档 / 时效错位）一个都不探
6无"缺陷不二过"闭环每个被人工发现的 bug 都没固化成自动断言，同类 bug 可永远复发
7输出无合理性闸门胜率 / 夏普无机器可判的合理性区间（胜率>95% 或 夏普>5 应告警），离谱但结构合法的输出直接放过去
8沙箱 / 真机环境割裂沙箱把"诚实报错"当 PASS，真实数据分支几乎不被自动跑到——正确性路径长期不验

四、系统性方案：7 根支柱

支柱 1 · 真值对照（Oracle 层）：对每个可判定正确性的模块建小样本已知答案夹具——回测用手算 / 独立 pandas 跑 2-3 只票 1 个月窗口，硬编码期望净值 / 收益，断言引擎数字在容差内吻合；预测筛选用确定性 mock 信号断言"引擎恰好选出预期集合"；估值分位喂已知 PE 历史断言分位值。
支柱 2 · 领域对抗探针（defect_probe.py，自主发现缺陷的心脏）逐类主动猎杀：前视偏差（对 generate(run_date=d) 分别喂"含后 d 日"与"截断到 d"，结果变 = 泄漏）；幸存者 / 时点（退市票剔除、universe 为时点快照）；复权漂移（qfq vs hfq 归一）；成本真实（零毛利策略真实成本下净值应 ≤0）；过拟合（样本内 vs 样本外对比）；涨跌停 / T+1 / 流动性（日收益不超 ±11%、无 T 日卖未持仓、无交易日外成交）；数据完整性 / 时效（每交易日有 K 线；run_date==真实最近交易日、陈旧角标正确——这一条能抓到刚修的 9-30 bug）。
支柱 3 · 故障注入 / 变异测试：建变异 harness，对生产代码施加已知变异（<→>、删成本项、max↔min、符号互换），跑套件；若全部仍 PASS 则构建失败。配套 10-15 个"种子缺陷"代表经典 bug 族，套件必须抓到，漏一个补断言。
支柱 4 · 独立验证者（双轨）：测试断言对着规格说明书（应该做什么）写，而非对着代码实际产出写；尽量让 QA 角色写 Oracle 断言，切断同源确认偏误。
支柱 5 · 缺陷不二过闭环：每发现一个人工 bug 立即沉淀为"先失败 → 后通过"的断言，维护 KNOWN_DEFECTS 注册表（id / 日期 / 根因 / 断言位置）；CI 每次改动跑全套（Oracle + 探针 + 变异）。
支柱 6 · 输出合理性闸门：给每个指标设机器可判的合理性区间（日收益 ∈ [-11%, +11%]、胜率 ∈ [0,100]、夏普超 ±5 即 flag），越界直接 FAIL 并上 dashboard。
支柱 7 · 环境一致性：把"沙箱诚实报错 = PASS"换成受控离线真实夹具（抓一小撮票的真实 bars / 指标随包发布），让正确性路径在 CI 也能跑，消除沙箱 / 真机割裂掩盖缺陷。

六、与现有脚本的改造映射

现有资产改造方向
verify_backend.py在"存在性 / 诚实报错"断言之外，新增回测真值对照、估值分位真值、一把尺子的强断言（数值在容差内）

defect_probe.py（新增）8 类领域对抗探针，CI 常驻
mutation / selfcheck harness（新增）阶段 0 测试自检闸：注入种子缺陷 → 确认测试 FAIL
KNOWN_DEFECTS 注册表（新增）每人工 bug 固化一条断言，缺陷不二过
离线真实夹具（新增）替代"沙箱诚实报错 = PASS"，正确性路径 CI 可跑
