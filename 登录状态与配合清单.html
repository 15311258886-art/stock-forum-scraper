三、淘股吧为什么"存了账号密码"也登不上

两个硬事实（均实测，非推测）：
  1. 程序只实现了「用户名 + 密码 POST 表单登录」（scraper/auth.py 的 generic_login）， 而淘股吧现行登录是扫码／验证码／MFA——没有密码登录入口，表单登录无处可提交。
  2. 配置里的登录网址 https://www.taoguba.com.cn/login/ 实测返回 404； 站点已迁至 www.tgb.cn。即便要提交表单，地址也是失效的。

结论：这条路在当前代码下走不通，不是"少存了一份凭据"的问题。 正确解法是改造成 Cookie 注入——扫码登录一次，把浏览器里的 Cookie 交给程序复用。

四、建议的下一步（二选一）

方案 A　改造为 Cookie 注入模式（推荐）

  1. 浏览器打开 www.tgb.cn，右上角点「登录」，微信扫码或手机验证码完成登录
  2. 确认登录成功后告诉我，我读取该站点的 Cookie（或给你一个一键导出的小工具）
  3. 我把 Cookie 加密存进本机凭据库，程序带 Cookie 抓取（本项目已有 Fernet 加密存储，不落明文、不上传）
  4. 我跑一次验证：用该 Cookie 访问一个受限页面，确认真的拿到登录态再交付
代价：需要我改一次代码；一次登录可用较长时间，失效后再扫一次即可。

方案 B　零改造，只抓公开内容

  1. 不登录也能抓淘股吧的帖子列表与正文（公开页已实测可访问）
  2. 代价：付费／积分／权限受限的实盘明细抓不到，界面上会如实标注「受限」
代价：数据完整度下降，但今天就能跑通，无任何风险。

五、不是"登录"能解决的（避免白费功夫）

境外源不可达（YouTube / Reddit / Reuters / BBC / arXiv / Google News）：属网络层封锁，登录页毫无作用。 两条可行路径：① 你提供一个可用的境外代理地址与端口，我接进抓取通道；② 沿用我已备好的云端中继方案 （GitHub Actions 在境外抓取后提交结果，本地再拉取——通道本人已实测可达），需要你提供一个 GitHub Token 或一个自建仓库地址。

东方财富股吧 / 雪球：此前实测分别为假页反爬与 WAF 拦截，且采集器尚未实现。若你要真正接入，属于"新增采集器"的开发任务，不是登录问题。
