② 登录流程 UI 状态类 —— 最容易被误读为「已登录」

三、根因：登录态在 SSO 域，而你的导出里没有它

淘股吧的登录态由独立 SSO 域 sso.tgb.cn 承载，不在 www.tgb.cn 本地：

  • 未登录访问任何需登录页面 → 302 到 https://sso.tgb.cn/web/login/index?url=<回跳地址>
  • 你导出的 Cookie 全部属于 tgb.cn / www.tgb.cn / shuo.tgb.cn / cj.tgb.cn → 没有一条属于 sso.tgb.cn

也就是说：真正的会话凭据在 SSO 域里，根本没被导出；导出的都是本域的风控 / UI / 埋点 cookie。 配合 loginStatus=qrcode（扫码弹窗状态），更像是扫码流程没有走完。

四、需要你的配合（三选一，推荐 A）

方案 A — 推荐：我开窗口，你扫码，我自动接管 最稳

  1. 你回一句「走 A」，我立刻弹出一个浏览器窗口（已准备好脚本）
  2. 在窗口里用微信扫码或手机验证码完成登录（程序不代填、不破解任何验证）
  3. 登录成功后不用管，脚本会自动识别并把 tgb.cn 与 sso.tgb.cn 两个域的 Cookie 一起存进你的加密凭据库
  4. 我随即跑一次受限页校验，通过就立刻开抓

你只需动作一次；全程我能自证「真的登上了」。

方案 B — 最快：从 Edge 复制一行请求头 30 秒

  1. 在 Edge 里确保已登录淘股吧（右上角能看到你的昵称）
  2. 按 F12 → 切到 Network（网络） 面板 → 刷新页面
  3. 点列表里第一个请求 → 右侧找到 Request Headers 里的 Cookie: 那一整行
  4. 把这一行（很长的 name=value; name=value; …）整段复制发我

注意：必须是网络请求头里的 Cookie（document.cookie 拿不到 HttpOnly 项）。 若其中看不到 sso.tgb.cn 相关条目，说明你当时其实没登录成功。

方案 C — 自己导出 JSON

装一个 Cookie 导出插件（如 Cookie-Editor），在淘股吧页面点 Export → JSON，把文件发我。 务必选「导出全部域」，确认包含 sso.tgb.cn。
