Competitive Teardown & Problem Restatement

提示能力的竞品拆解，与题目重写

你要的是"更深入"而不是"更大"。这份文档先做竞品拆解，但结论可能与预期相反： 我们缺的不是提示的数量，是提示的可信度。所有建议都建立在该系统自己的数据库实测之上。
数据来源：viewer/app.db 实测 信号账本 111 组 / 预测登记 360 条 2026-10-29

一、先说一个与"加功能"相反的结论

在讨论学谁之前，必须先看我们自己的账本。我从系统数据库里直接查了三组数字，它们指向同一件事：

0
预警记录条数
watch_alerts 表为空。到价提醒、突破提醒的代码路径存在，但从未产生过一条记录——这类功能是空壳。
T+5
几乎全部信号为负
111 组信号账本里，T+5 平均收益为正的不到 15 组，且每组样本仅 1~16 个，统计上不可用。
45%
次日命中率 ≈ 抛硬币
逐日预测 347/360 已结算，单日命中 3/20 到 14/20 剧烈摆动，看不出稳定优势。
这件事的含义：如果信号本身没有信息量，那么"提示得更快、更漂亮、更多渠道"只会让你更早、更准地执行一个没有优势的动作。对标竞品的第一价值不是抄功能，而是搞清楚他们的提示为什么有人信。

还有一个更隐蔽的问题：系统里存在两套互相矛盾的账本。一套是小样本的 predictor_score（每组几十到几百个样本，波动极大）；另一套是 signal_backtest（单条信号九千余样本，例如"KDJ 超买死叉"20 日胜率 42.0%、夏普 −0.299）。而评分加权用的是前者。这等于用噪声去校准信号。

逐条看，哪些值得学，哪些是陷阱

值得学（补的是可信度，不是数量）

  • 结论带回测路径——最便宜的高价值改造。我们已有九千样本回测库，只是没印在提示旁边。这一条就能把"提示"变成"有依据的提示"。
  • 异动归因——我们有天然优势：论坛与短视频本身就是"为什么涨"的原始文本。缺的是把它们结构化到"驱动逻辑 + 催化时点 + 可证伪条件"。
  • 题材生命周期分阶段——AI 复盘里已有 stage 字段，但那是定性判断；应改为用涨停家数、连板高度、成交占比算出启动/发酵/高潮/退潮。

看着诱人但是陷阱

  • 云端秒级推送——前提是你的信号在扣费后有正期望。目前 T+5 为负，推得越快执行越准，亏得越干脆。技术难度低，价值排序应靠后。
  • 更多指标、更多板块、更多榜单——典型"更大的版本"。在验证体系没修好之前，每加一个信号都在放大噪声。
  • 照搬一致预期数据——慧博的预期差建立在卖方研报库上，我们没有这个数据源，硬做只能是伪精度。

三、我们有哪些竞品拿不走的东西

抄竞品之前要知道自己守什么。以下五项是结构性差异，不是功能差异：

  1. 论坛博主的可结算战绩。韭研靠人工挑"优质作者"，我们能用 5327 条信号记录 + 21 人跟踪表算出每个人的历史胜率与超额。这是唯一能回答"这个人的话值多少钱"的资产。
  2. 抖音 / B 站内容源。竞品完全没有。短视频的情绪传导通常早于论坛文字，是天然的前置指标。
  3. 港美股与海外情绪联动。跨市场传导链，国内软件普遍弱。
  4. 你自己的准则库。AI 复盘会读你的九条交易准则——没有任何商用软件能做到这种个性化纪律约束。
  5. 预测登记 + 事后结算的完整闭环。prediction_run / prediction_item 已经有逐日登记与 T+1/T+3/T+5/T+10 结算字段。这是"可审计"的骨架，绝大多数产品不敢做，因为做完就要面对自己的成绩单。

四、你问的四个问题

（1）这个领域的顶尖专家会做、而你没要求的事

  1. 先定义"有用"，再谈优化。是 T+1 命中？还是 T+1 到 T+5 的超额？口径不定，后面所有工作都无法评判。
  2. 一切收益减基准。牛市里任何信号都"赚钱"。必须减掉同期指数或等权组合，才算信号有效。系统里已有 bench_t1/t3/t5 字段，但没进展示口径。
  3. 扣掉交易成本。印花税千分之一、佣金、滑点。T+1 均值 +0.075% 这种数字，成本一算就没了。
  4. 多重检验校正。试一百个指标，总有五个好看。不做 FDR 校正，等于自己骗自己——这正是 111 组账本里那些"好看但样本个位数"的来源。
  5. 样本外检验与幸存者偏差处理。退市、停牌、ST 必须留在样本里，否则回测必然虚高。
  6. 预测先登记、口径不许改。预注册机制。事后调整口径是这类系统最常见的自欺方式。
  7. 合规边界。任何对外输出的"建议"都涉及投顾资质边界，表述必须落在"数据与统计"而非"投资建议"。

（2）他们会从哪些原始素材入手，而不是你已经整理好的素材

我们目前用的（已加工的聚合值）

  • 板块净流入金额、板块涨幅排名
  • "机构席位净买 +44.89 亿"这类聚合标签
  • 论坛情绪净多 +169（先算成净多比）
  • AI 复盘输出的结论与主线判断

专家会直接用的（带时间戳的原始事件流）

  • 龙虎榜原始营业部名称与买卖金额（不是"机构席位"这个聚合标签）
  • 涨停首封时间、封单量、炸板次数、回封时间
  • 公告与互动易问答原文及发布时刻
  • 论坛原始帖子（发帖时间戳、作者、楼层顺序），不是情绪分
  • 融资融券逐日、北向逐笔、大宗交易明细与折溢价
  • ETF / 可转债折溢价（资金真实意图的旁证）

差别不在"更原始"，而在"顺序"。聚合会丢掉节奏：一只票是开盘秒板还是尾盘偷袭、是首封还是回封、封单是递增还是撤单——这些顺序信息在算成"涨停=1"的瞬间全部消失，而它们恰恰是判断持续性的主要依据。

（4）除了你我，还有什么能证明结果是对的

  1. 可独立复算的原始行情。交易所与巨潮的日线/逐笔是公开的，任何人拿我们的预测登记表都能自己算出命中率。
  2. 中证指数公司的官方基准。超额收益用官方指数，不用自建基准，避免"自己定标准自己及格"。
  3. 公开因子库对照。如 CNE6 / Barra 风格因子，验证我们的"超额"不是某个风格暴露的伪装。
  4. 时间戳审计。prediction_run 的 created_at 是不可篡改的登记时点，第三方可核对"预测是否事后修改"。
  5. 可复现性。换一个人按文档跑一遍，能否得到同一组数字。这是最硬的验证。
  6. 公开的第三方研报与一致预期（Wind / Choice），用来交叉验证我们对某只票的归因是否与主流认知一致或存在分歧。

五、改写后的题目

原题的核心是"改造并优化这个查看器"——它是一个工程命题，天然导向"做更多功能"。按上面四条要求，它应该被重写成一个验证命题：

原 题 目
对股票论坛可视化查看器进行底层重构与优化，梳理链路、简化代码，并接入 WorkBuddy 算力、优化数据源呈现速度。
问题：目标落在"更稳、更快、更简洁"，是工程质量，不是研究质量。做完之后，提示是否更可信，仍然无法回答。
重 写 后
以"提示是否可结算"为唯一验收标准，改造现有论坛查看器：

① 把所有提示统一到相对官方基准、扣除交易成本后的 T+1 / T+3 / T+5 超额收益这一个口径；

② 输入从聚合指标下沉到带时间戳的原始事件流（涨停首封/回封、营业部原名、原始帖子时间序）；

③ 每条提示必须携带历史样本量、胜率、基准超额与失效条件，样本不足则显式标注"不足以判断"；

④ 建立预注册—结算纪律：预测先登记、结算自动跑、口径锁定不可事后修改；

⑤ 交付物不是新面板，而是一份能被第三方独立复算的信号审计报告。
这一版把"做大"换成"做准"：功能可能变少，但每个留在界面上的提示都必须能回答"凭什么"。验收标准从"跑得通"变成"算得清"。

新题目明确不做的事

  • 不新增数据源（除非为了替换掉一个聚合指标）
  • 不新增展示面板（除非它能承接审计结论）
  • 不在验证体系修好前增加任何新信号
  • 不做云端秒级推送（价值排序在信号修好之后）

如果只能做一件事

把已有的九千样本回测库（signal_backtest）接到界面上，让每一条提示旁边直接印出它的历史胜率与基准超额，并把小样本的 predictor_score 降级为参考、不再参与加权。 这一件事改动量最小，却能把"提示"从看起来有道理变成有账可查——而这正是竞品里最贵、我们最缺的那一层。
