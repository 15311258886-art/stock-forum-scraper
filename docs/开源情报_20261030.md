# 开源情报：把 GitHub 上的量化说法当假设，不当结论

> 2026-10-30 建立｜模块 `viewer/oss_mine.py`｜接口 `/api/oss`｜调度 `oss_daily` 16:00

---

## 一、为什么做这件事

GitHub 上的量化项目有三个别的信息源没有的优点：**免费、规则明牌、有社区压力**。
论坛里一句「这票要涨」无法证伪，但一个仓库里写着 `ret1 >= 4 and volume_ratio >= 1.5`
——这句话可以拿去跑数据，然后在 40 分钟内被判定为真或假。

但直接搬过来会踩三个坑，这也是本模块只做「抽规则」不做「抄代码」的原因：

**① 高星 ≠ 高价值。** 星数最高的是回测框架（akquant 2,477★）和黑盒模型
（Factor-Research 422★，LSTM/ResNet，自称 IC=0.065）。它们不产生可执行规则，
只产生不可解释的曲线。真正有操作价值的规则，反而藏在 5 星的
`dcimring/stockbee-dashboard` 这种仓库里——因为规则全是明牌。

**② 他们的回测不能用。** 这些项目大多没有本地全库：样本几千行、单票时间序列、
甚至带未来函数（用当日收盘价买入需要盘后才知道的信号）。同一个「4% 突破」在美股
ETF 上有效，在 A 股 T+1 严格口径下可能正好相反。

**③ 信息本身会变成噪声。** 这正是这一轮清理论坛链路时确认过的事：**缺的从来不是信息，
是过滤**。所以本模块的产出不是「又一个荐股源」，而是一份**证伪清单**。

我们的独特优势只有一条：**1,700 万行日线（1990 至今）+ 一套严格口径引擎**
（`hypo.py`：d 盘后知情 → d+1 收盘建仓 → 减同日全市场等权 → t 按日聚合）。
所以定位是——**用我们的数据，重跑他们的假设**。

## 二、三条自我约束（写进代码，不靠自觉）

| 约束 | 理由 |
|---|---|
| **不抄代码** | License 复杂；数据层不同，抄来跑不通反而增加负债。只抽「条件 + 方向 + 为什么可能有效」 |
| **不信他们的回测** | 样本浅、常带未来函数。他们的结论一律不信，只借他们的假设 |
| **refuted 也要入账** | 被推翻的结论比没结论更有价值：下次不再重复挖，同时写进 AI 上下文防止模型误用 |

## 三、机制

```
GitHub 检索（4 组关键词，每日）
      ↓  候选仓库入池，标 A/B/C（A=规则可回测 B=结构可借鉴 C=不采用）
抽规则 → 写成 predicate（只能表达「字段 运算符 数值」，表达不了的不硬塞）
      ↓
hypo.evaluate 严格口径回测（主区间 + 前后两段稳健性）
      ↓
判定：active / refuted / unstable / marginal / unsupported / invalid
      ↓
落表 oss_rule → /api/oss → 前端「开源情报」→ AI 复盘上下文
```

**判定阈值与 `evidence.py` 完全一致**，并新增两档：

- `unstable`：均值与 t 符号相反，或前后两段方向相反 → 结论不可靠
- `marginal`：|t|≥2 但 |超额|<0.3% → 统计显著、经济无意义

## 五、长样本复核：这才是能下结论的部分

主结果是 14 个月样本，**不足以支撑「结构性」的结论**。所以另开一条通道：
直接用 `data/kline_daily.db`（1990 至今全量日线）重算两条最关键的规则。

| 规则 | 14 个月样本 | **2020 年以来（1,626~1,645 个交易日）** | 方向 |
|---|---|---|---|
| 均线多头排列 | −0.32%，t=−2.11 | **−0.50%，t=−9.96** | 同向 |
| 4% 放量突破 | −0.57%，t=−2.47 | **−0.55%，t=−10.23** | 同向 |

两套样本完全同向，且长样本 t 值强了一个量级。**可以判定为结构性现象，
不是某段行情的偶然。** 这是本轮唯一敢写进「知识」而不是「观察」的两条。

## 六、一个反直觉的细节：均值 +1.18%，却是最不能信的一条

| 规则 | 均值超额 | t | 看起来 |
|---|---|---|---|
| 20 日跌幅 >20%（反转） | **+1.18%** | **0.40** | 11 条里最诱人的数字 |

如果只看均值，这条会被写成「大跌之后必有强反弹，抄底有效」。但按日聚合后的 t 只有 0.40——
意思是：**绝大多数日子这个效应是 0，是少数几天的极端反弹把总均值拉高了。**

这正是严格口径存在的意义。同类型的还有一个：
`dist_high250 >= -25` 得到「均值 +0.04%、t=−1.00」，两者符号相反——
一半以上的样本日在跌，少数创新高的票把均值抬到正。这种数字如果不检查，
会被写成「贴近新高会涨」，然后拿去指导交易。

所以判定里有一条硬规则：**均值与 t 符号相反 → 直接判 unstable，不进任何结论。**

## 七、自检发现的问题（这次真正挖出来的）

自检脚本：`tools/oss_selfcheck.py`（16 项）+ `verify_oss.cjs`（10 项），全部通过后才有交付。

### ① 最大的一处：所有回测的样本深度只有 14 个月

`stock_indicators_daily` 从 **2025-08-18** 才开始，共 288 个交易日。
而 `hypo.py` 的所有回测（包括 `evidence.py` 里几十条 claim）都建在这张表上。

此前没有任何地方把这句话写出来。也就是说：**我们一直在用 14 个月的数据，
讲「实测」「结论」「t 值」这些词。** 这不是造假，但确实是口径缺失——读者会默认
「实测」= 长期验证。

本次的处理（不是掩盖，是披露 + 补通道）：

1. `/api/oss` 增加 `data_span` 字段，前端在**所有数字之前**用黄条强制展示：
   「主结果样本 2025-08-18 ~ 2026-10-29（288 个交易日，约 14 个月），未覆盖完整牛熊」；
2. AI 复盘上下文同样写入这条边界，防止模型把 14 个月的结论当长期规律引用；
3. 新增长样本复核通道（`kline_daily.db` → 2020 年至今），对关键规则做跨周期验证。

**待办**：把 `stock_indicators_daily` 的历史回补到 2020 年（从 1,700 万行日线重算指标），
一次性解决所有模块的样本深度问题。这是下一步最该做的事。

### ② `ensure_schema` 的模块级布尔缓存会坑换连接

原实现用 `_ensured` 做「只建一次」缓存。第一个连接建过表后置 True，
第二个连接（DB 重连、内存库、集成测试）就不再建表，后续查询直接 `no such table`。
改为每次查一次 `sqlite_master`——微秒级开销，换掉一个只在换库时才爆、极难复现的坑。

### ③ `payload()` 读表失败会把异常抛给请求线程

表被清空/未初始化时，`_rows()` 会抛异常并打到前端。改为降级返回
`available=false` + 原因，前端显示「尚未跑过回测」而不是报错弹窗。

### ④ 前端三个表达问题

- 「有效 0」用绿色 → 绿色读作「良好」，改中性灰；
- 表里 `-1` / `-2.47` / `+0.036` 混排 → 统一两位小数；
- 「候选 23 个」会被误读成「已消化 23 个」→ 拆成「候选 / 待分级」两个计数。

### ⑤ 验证脚本自己踩的坑

关闭新手引导时用 `offsetParent !== null` 判可见性——但 `#firstRunModal` 是
`position: fixed`，其 `offsetParent` **恒为 null**，于是永远找不到按钮，截图一直被弹窗挡住。
改为按 id 直接点 + 摘除遮罩兜底。

## 八、边界（不装作做了）

1. **主结果样本仅 14 个月**，未覆盖完整牛熊；只有两条规则做了长样本复核；
2. **谓词表达力有限**：只支持 1~2 个「字段 运算符 数值」，多因子打分、排序分位
   这类规则暂时翻译不进来，硬塞只会测出一个和原规则无关的东西；
3. **仓库分级是人工判断**，扫描是自动的。面板把「候选数」与「待分级」分开显示；
4. **GitHub 扫描依赖网络**，失败静默降级（不阻塞回测），所以「今天没扫到」可能只是网络问题；
5. 美股/港股/印度标的的仓库一律判 C 不采用——**标的不同源，规则不可迁移**。

### 唯一改判的一条：`reversal_20`

394 日窗口首次跑出 `t=2.49`（唯一 active）。按新纪律必须拉长样本，结果**收益在 T+20 而非 T+5**：

| 持有期 | 逐样本超额 | 按日超额 | t | 胜率 | 样本 |
|---|---|---|---|---|---|
| T+5 | +1.71% | +0.11% | 1.23 | 56.8% | 2581 日 / 37.4 万 |
| T+10 | +3.19% | +0.24% | 1.89 | 58.6% | 2574 日 / 37.1 万 |
| **T+20** | **+5.33%** | +0.42% | **2.24** | **61.3%** | 2564 日 / 36.9 万 |

- 这是本项目**第一次出现方向为正、且长样本 t>2 的公开规则**。
- 但它是 **20 个交易日级别**的修复，不能当「今天买明天卖」；
  日均约 145 只命中，属宽口径条件，不是稀缺信号。
- 与「短线 8 形态全负超额」不矛盾：那 8 个是涨停 / 创新高 / 三日累跌，
  **没有「20 日深跌 20%」这个深度超卖条件**。
- 已按长样本结论把该行改写为 `horizon=20 / +5.33% / t=2.24 / active`，
  T+5 的不显著结果放进 `cross_*` 列做对照。

### 顺带修掉的虚假披露

`oss_mine.data_span()` 原来直接报**指标表**的起止。表扩到 2627 天后，
面板会显示「样本 2016~2026 共 2627 个交易日」，而规则实际只跑了最近 394 个交易日 ——
两者不是一回事。现在分开披露：**规则实测窗口**（取各规则天数的中位数）+
**指标表全跨度**（单独一行），并在提示词里写明「不要读成结论用了全部历史」。
