# 论坛 / 大V 信号可参考性实证（2026-10-30）

> 触发：进哥提问「淘股吧、雪球这批人的持仓/推荐/帖子，追踪效果到底怎么样？有正向价值还是反向价值？」
> 结论先行：**有值，但方向是反的；且能用的只有一个切面。**

## 一、先分清四类数据（它们不是一种东西）

| 数据 | 表 | 规模 | 可测性 |
|---|---|---|---|
| 持仓快照 | `positions` | 271 条 / 53 人 | **不可测** |
| 交割单 / 实盘日记 | `trades` | 1539 条 / 503 人 | 可测（价格缺失，用 K 线反推） |
| 帖子 + 提及 | `posts` / `stock_mentions` | 17,513 帖 / 3,527 条可测提及 | 可测（情绪标签噪声大） |
| 人物战绩 | `person_scores` | 739 人 | **基本是空壳**（见第五节） |

### `positions` 为什么不可测（硬事实）

```
buy_price 非空 = 0    sell_price 非空 = 0    buy_time 非空 = 0
post_time  = 全部空串（267 条）
action     = 全部「关注/操作」
```

没有时间戳就没有时序，没有价格就没有收益。这 271 条是**某一时刻的静态快照**（淘股吧"重点关注/操作股票"），
不是历史流水。「6 月推荐、11 月还在」这种担忧对它反而不适用——它压根没有 6 月。

## 二、口径（与 `probe_avoid_signal.py` 一致，便于横向比较）

- 收益：`close[t+N] / close[t] - 1`，t = 事件日对齐到当日或之后最近交易日
- 超额：个股收益 **− 同日全市场均值**（截面 demean，剔除大盘）
- t 值：**先按日聚合再检验**。不这么做，同一天几千个样本会被当成独立样本，t 值虚高几十倍
- 样本期：2026-08-01 起（K 线表只到 2025-08-18，更早的交割单测不了）
- 脚本：`tools/probe_crowd_signal.py`（主表）、`tools/probe_crowd_robust.py`（稳健性）

> **数值口径注意**：两个脚本的均值不是同一个统计量，不要混着比。
> - 主表 `probe_crowd_signal.py` 给的是**事件级平均**（每个事件等权）：HOLD = −3.08%、淘股吧 HOLD = −5.36%
> - 稳健脚本 `probe_crowd_robust.py` 给的是**按日聚合后的日均值平均**（每天等权）：HOLD = −3.38%、淘股吧 HOLD = −6.41%
>
> 两者 t 值相同（都由日聚合序列算出），均值不同是因为加权方式不同。下文表格统一用**日均口径**，
> 因为它与 t 检验、与三项稳健性检验同源。

### 稳健性怎么判（单看全样本 t 值不够）

样本只有 2-3 个月，相邻日期的样本往往是同一批人、重叠持仓，自相关强。三项检验全过才算信号：

1. **时间对半切** —— 前后 50% 两段必须同号（挡行情噪声）
2. **按周聚合再算 t** —— 降低同日重叠持仓造成的伪显著
3. **剔除样本最多的 3 天** —— 结论不能翻转（挡极端日绑架）

## 三、结果

| 信号 | n | T+5 超额 | t | 三项检验 | 判定 |
|---|---|---|---|---|---|
| 实盘选手 **持仓不动**（HOLD） | 135 | **−3.38%** | −3.16 | 全过 | ★可用（反向） |
| 淘股吧 **帖子看多** | 487 | −1.41% | −2.02 | 同号 | 弱可用（反向） |
| 实盘选手 **卖出**（SELL） | 661 | −1.21% | −0.94 | 同号 | 不显著 |
| 实盘选手 **买入**（BUY） | 475 | +0.28% | +0.36 | **反号** | 噪声 |
| 论坛看多（全站） | 2011 | +0.13% | +0.29 | 同号 | 噪声 |
| 论坛看空（全站） | 1200 | +0.41% | +0.71 | 同号 | 噪声 |
| 东财帖子看多 | 983 | +0.72% | +1.35 | **反号** | 噪声 |

分源看，**淘股吧 HOLD 最强：−6.41%，t=−4.59**，剔除样本最多的 3 天后仍有 t=−4.75，118 位作者分散（前 3 名仅占 14%），不是被少数人主导。

> 东财、新浪的情绪信号前后半段全部反号（东财看多 前半 +1.83%/t=2.95、后半 −0.40%），
> 说明这两个源的情绪标签**当前不可用**。原因见 `posts.sentiment` 是关键词匹配：
> 「各位老师，360 买的，什么时候能回本」被判成"看多"，这类噪声占比很高。

## 四、最重要的一条：这批数据是「事后晒单」，不是「事前信号」

三类动作在**发帖之前** 5 日的平均超额：

| 动作 | 事件前 5 日超额 | 事件后 5 日超额 |
|---|---|---|
| HOLD | **+6.37%** | −3.08% |
| BUY | **+10.92%** | +1.33% |
| SELL | **+10.07%** | −0.24% |

事件前跑输大盘的比例只有 23% / 26% / 32%。

翻译过来：**晒出来的票，是已经涨完一波的票。** 所以跟单 BUY 拿不到超额——你接的是别人的浮盈。
这也解释了为什么"买入"这个最直觉的信号反而是 zero：不是他们选得差，是**晒单时点滞后于涨幅**。

### 被数据否掉的三个假说（后人勿再推回来）

| 假说 | 检验 | 结果 |
|---|---|---|
| 「被套了才死拿」（HOLD 亏是因为套牢） | 事件前 5 日超额 | **否**：只有 23% 跑输，多数是赚着不走 |
| 「涨完就回吐」（追高必跌） | 前 5 日超额 vs 后 5 日超额相关性 | **否**：r = **+0.206**（正），追高不必然跌 |
| 「老手更准」（高频作者质量更高） | 按作者事件数分层 | **否**：8-19 次组 T+5 +3.08% 但胜率仅 40%，符号不稳 |

## 五、系统现状：那个「人物战绩」面板几乎是空的

`person_scores` 表 739 人，实际情况：

```
win_rate_5d 非空 = 11 人（其中 7 人 = 100%，4 人 = 0% —— 每人只有 1-2 个事件，不是胜率是猜对猜错）
computed_at     = 2026-09-26 03:17（一个多月未更新）
trade_count>0   = 46 人 / 54 条
```

而 `trades` 表有 1539 条、503 个作者，其中 **1148 条（75%）的作者能在 `persons` 里找到**。
数据是有的，没进评分。两个原因：

1. **名单筛选口径**：评分名单按「提及数」筛出 739 人，只发交割单、发帖少的人被漏掉
   （503 个交割单作者里只有 63 个进榜）。
2. **行情取数**：`computed_at` 那次大概率用了 `--no-net` 或联网失败，导致绝大多数事件
   `forward_return` 取不到 → 只剩 11 人算得出胜率。

→ 修法：重建时改用本地 `stock_indicators_daily` 算收益（不联网、不依赖 kline_cache），
名单改为「有交割单 或 提及数达标」，覆盖率可从 11 人提到数百人。

## 六、可落地项（按性价比排序）

1. **HOLD 作为避坑叠加**（唯一统计稳健的反向信号）。但它稀疏（135 条/17 个交易日），
   只适合做候选池的"额外警示"，不能当独立策略。注意：需先修 `HOLD` 提取——
   当前会把「只是跟踪观察」的票也标成持仓（如 `老张择势` 那条帖），污染约一到两成。
2. **淘股吧帖子看多 → 负向提示**。样本 12 个交易日，建议再观察一个季度再上线。
3. **修 `person_scores`**（第五节），让「谁值得关注」这个功能真正有数——目前它是空的。
4. **不建议**：把 BUY 当正向信号、把东财/新浪情绪当信号、用 `positions` 做任何时序判断。

## 七、这份实证的天花板（不掩饰）

- **样本只有 2-3 个月**（2026-08~10），有效交易日 17-29 个。所有结论都是"当前环境下"的，
  环境漂移后需重跑。
- **K 线只到 2025-08-18**，2025-08 之前的交割单无法回测。
- **交割单 price 字段 99.9% 空**，只能用收盘价反推，无法复现真实成交价，也无法算手续费/滑点。
- **晒单类数据存在不可根除的选择偏差**：亏了的人不晒。本实证的 T+5 结果因此偏乐观，
  真实"跟随收益"只会更差，不会更好。
- HOLD 为什么是负的，**我解释不了机制**。三项检验都过了、作者足够分散，但"为什么"没有答案。
  在没有机制解释前，它只能当弱信号用，不能当强因果。

## 复现

```bash
python tools/probe_crowd_signal.py  --start 2026-08-01   # 主表：各信号 T+N 超额
python tools/probe_crowd_robust.py                        # 稳健性：三项检验
```
