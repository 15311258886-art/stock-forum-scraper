## 2. 表二 · 速度对照

| 任务 | 我们（现状） | 它（自述/实测） | 差距性质 | 判定 |
|---|---|---|---|---|
| 全市场日线，一次覆盖 | **逐只抓新浪**：`tools/build_kline_db.py :: _fetch_one` → `viewer/server.py :: api_kline`；`viewer/kbase.py` 增量 `workers=2`，代码注释写明「新浪限流敏感」。全市场约 **5500 只 = 5500 次请求** | `tdx_daily_package`：**一次请求**拿某交易日沪深北全市场 **52314 行**（实测：沪 27810 / 深 24128 / 京 376） | **量级差，不是百分比差**（请求数 5500 : 1） | **两者都要** |
| 单票日/周/月 K 线 | 单入口直连 | 腾讯 K 线有**三个入口轮换**：`web.ifzq.gtimg.cn` / `proxy.finance.qq.com/ifzqgtimg` / `ifzq.gtimg.cn`；**单入口约 600 次后返回空 JSON**，失败后该入口**冷却 120 秒**；日/周/月单次 **≤640 根**，超出按段分页（day 段 700 天） | 机制差（它把「限流」做成了调度问题，我们只写了「敏感」两个字） | **两者都要**：这套轮换 + 冷却**直接照抄**，不需要它的代码 |
| 分钟线 | 未做（本地无分钟库） | 单次 **≤320 根**；**第 8 字段是换手率基点（÷100 才是百分数，不是成交额）** | 口径坑 | **保留我们（暂不做）**，但把这个坑记进文档，将来做的时候别再踩 |
| 北交所 | 逐只抓，形状同沪深 | **腾讯 K 线对北交所只回最新 1 根**，要拿历史必须改走盘后包 | 口径坑 | **引入它**（盘后包这一条路），否则北交所历史不可得 |

**表二结论（判断）**：
1. 逐只抓 vs 一次全量，是**架构级**差距。5500 次请求意味着 5500 次限流风险、5500 次重试机会、
   以及「今天补齐跑了一半失败」这种半成品状态；一次请求拿 52314 行是**原子**的。
   这一条的收益比本文里其他任何一条都大。
2. 但注意：这条收益**不需要它的代码**就能拿到 —— 「三入口轮换 + 失败冷却 + 盘后全量包」
   是三句话的机制，我们自己实现一遍比 vendor 一个 438KB 单文件干净得多。
3. 分钟线口径那个坑（第 8 字段是换手率基点）说明它是**踩过坑才写下来的**，
   这份「踩坑清单」的价值不低于它的代码本身。

## 4. 要接必须先解决什么

这一节是事实，不是判断。**当前状态下「把它的代码 vendor 进项目直接 import」这条路不通。**

### ① 取件：**已解决**（2026-11-03 同日推翻）

> ⚠️ **本节原判断「必须人工下载」是错的，原因不是情况变了，是当时排查不彻底**——只试了 `raw.githubusercontent.com` 直连，没试反代 CDN。
> 下面是当时的记录（保留），后面是后来的实测。

**原记录（保留）**：

| 障碍 | 事实 |
|---|---|
| 直连被墙 | 本机 shell 直连 `raw.githubusercontent.com` **被墙（SSL EOF）** |
| 连接器不能落盘 | GitHub 连接器只能把内容**读进上下文**，无法写文件 |
| 单文件超出读取上限 | `SKILL.md` 有 **438KB**，超出单次可读上限 |

**2026-11-03 实测推翻**（逐个通道探测结果）：

| 通道 | 结果 |
|---|---|
| `raw.githubusercontent.com` | ❌ SSL EOF |
| `cdn.jsdelivr.net` / `gcore.jsdelivr.net` | ❌ 不通 |
| `raw.gitmirror.com` / `ghfast.top` | ❌ 不通 |
| **`gh-proxy.com` 反代** | ✅ **200，438,587 字节，与预期完全一致** |
| `api.github.com` | ✅ 通（base64 JSON） |

**结论**：`curl "https://gh-proxy.com/https://raw.githubusercontent.com/simonlin1212/a-stock-data/main/SKILL.md"` 一把下完，**不需要人工介入**。
已按此装配成本地 skill：`~/.workbuddy/skills/a-stock-data/`（主文件当索引 + `references/` 16 章按需读 + `vendor/` 原版全文保真）。详见该目录下 `SOURCE.md`。

### ② 拆件：它是单文件，我们是模块化项目

- 无版本号、无 `setup.py`、无 `requirements`：**下次同步时无法 diff**，只能整份替换。
  接的时候必须自己锁一个 **commit hash** 并在文件头写清「vendor 自哪个 commit」。
- 438KB 单文件里 85 个入口全在一个文件：**整包 import 会把 34 个源的失败模式一次性带进来**
  （任何一个源在 import 期就要网络/鉴权，都会变成我们的启动依赖）。
  正确做法是**按需 vendor 2~3 个函数**，而不是整份拷进 `extlib/`。
- Apache-2.0：保留版权与 NOTICE 声明。

### ③ 口径：两个源都对，等于两个源都不对

接进来之前必须逐条对齐下面这些，**每一条都能让结论反向**：

| 口径项 | 为什么必须对齐 |
|---|---|
| 复权方式 | 我们 `kbase` 有 `adj` 字段（`KBASE_ADJ` 口径）。它的日包是原始价还是复权价，直接决定箱体高低点算出来是不是同一个数 |
| 交易日历 | 我们 `_drop_unformed_dates()` 会剔除「只有一只票有 K 线」的半日。它按交易所归档，口径未必一致 —— 混用会让回测的 T+N 错位（这个坑 2026-10-28 我们踩过一次） |
| 成交额单位 | 我们 `universe_box` 的流动性门槛用 `close × v` **近似**成交额。它若给真实成交额，两边的「3000 万」不是同一个东西 |
| 分钟线第 8 字段 | 是**换手率基点**（÷100 才是百分数），不是成交额。直接当成交额用会静默错 |
| 北交所 | 腾讯 K 线只回最新 1 根 → 必须走盘后包。用它补齐时要么全走盘后包，要么北交所单独一条路 |

### ④ 它**有**测试（本节原写「没有测试」，2026-11-03 更正）

> ⚠️ **原判断错误。** 当时只看了 `docs/` 目录，没拉仓库文件树。实际它有 `tests/` 目录：
> ```
> tests/test_official_data.py   16,061 B
> tests/test_v310_sources.py    27,978 B
> tests/test_v39_sources.py    103,228 B
> tests/test_valuation.py        3,658 B
> 合计 146KB / 4 个文件
> ```
> 已随装配件下载到 `~/.workbuddy/skills/a-stock-data/vendor/tests/`。

**但结论方向不变**：这些是「能跑通」的测试（作者自测接口可用），不是「和我们的数一致」的测试。
接进来仍必须**自建 golden fixture**：固定几个已知日期，把它取到的数与我们已经验证过的 `kbase` 数对一遍，差异超阈值就不接。
**「它有测试」≠「它和我们的数一致」。**

### ⑤ 不回测，不改判据

它明确不带回测引擎。所以引入它**只增加特征与事件，不改变我们的验收口径**：
任何新维度进来，仍要走三期因子门禁（`|IC| ≥ 0.02 / |ICIR| ≥ 0.30 / |t| ≥ 2.5`、
有效 IC 天数 ≥ 120）与 `tools/ab_box_mode.py` 那种**无前视配对 A/B**。
D71 刚给过一次教训：**有 IC ≠ 接进去就更好**。这一条对本文的 P1~P4 全部适用。

## 5. 一句话结论

> **它是补缺，不是替代。** 23 个维度里 **9 个「保留我们」**（全是它没有的判据与舆情层）、
> **13 个「引入它」**（全是我们最薄的宏观与官方口径层）、**1 个「两者都要」**
> （全市场日线：两条路并存，用它的做全量底稿与校验）。
>
> **取件已不再是障碍**（2026-11-03 用 `gh-proxy.com` 反代下载成功，已装配为本地 skill）。
> 但「拿到文件」和「接进内核」仍是两件事，先后顺序不变：
> **先照抄它踩过的三个坑**（一次全量、入口轮换与冷却、北交所走盘后包）——这三条改的是采集层，
> 不需要过因子门禁，当天就能见效；**再谈引入新维度**——那必须过口径对齐 + golden fixture + 无前视配对 A/B。

**2026-11-03 装配后实测（不是上游自述，是本机跑出来的）**：

| 端点 | 实测 |
|---|---|
| §1.1 `tencent_quote` | 0.20s，茅台 1457.66 元 / PE 22.18 / PB 6.72 |
| §1.3 `tdx_daily_package("2026-09-18")` | **9.40s，52,314 行 × 14 列**；沪 27,810 / 深 24,128 / 京 376；茅台收 1257.12、成交额 31.36 亿 |

对照我们现状：逐只抓新浪 5,500 只 = 5,500 次请求。**9.4 秒 vs 5,500 次请求**，这才是 P0 该先做的事。
