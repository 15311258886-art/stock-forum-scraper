# 方案：怎么让武器库真的能用

日期：2026-11-05　｜　起因：进哥指出「武器库里全是武器，但你不用、找了堆理由不用、用了也不会用」

---

## 一、先把我的错摆清楚（四件事，都是方法上的）

### 错 1：我把「回测」缩窄成了「用历史数据算收益」

于是凡是没历史的工具就判死刑。这是把工具的问题变成了数据的问题，然后停在数据上。

**回测的本质是「先写下判断，再让时间打分」，不是「必须有历史数据」。** 没有历史，
可以往前记。这两件事的差别，就是我之前把 10 个工具判死的全部理由。

### 错 2：我用同一把尺子量所有工具

`oss_high_vol` 用「选股器」的标准看是 −1.386pp（很差），用「排除器」的标准看是
「被它剔掉的票确实更差 1.4pp」（方向完全正确）。**同一个数，两套标准，一个死一个活。**

而工具至少有四种角色，验收标准各不相同：

| 角色 | 职责 | 验收标准 | 现在被误用的 |
|---|---|---|---|
| 选股器 | 从池里挑出更好的 | 池内区分力 > 0 且显著 | — |
| **排除器** | 把不能碰的先剔掉 | **被剔的比没剔的更差**（允许为负） | oss_high_vol、gate_admit、avoid_c |
| **描述器** | 标注当前形态 | 稳定可复现即可，**不承担收益预测** | db_wave、near_high、shrink_vol |
| 排序器 | 决定先看谁 | 分位单调性 | kronos、pillar_* |

我拿第一套去量了全部 31 个。

### 错 3：我只做了「无条件」检验，从没建「什么时候用」的路由层

一个工具在**全样本平均**上是 0，不等于它在**特定行情**里也是 0。我把「平均 0」直接
读成「没用」。这是第二次犯同一个错（上一次是拿 3 年数据否定 6 个月持有期的工具）。

### 错 4：我把「等一年」当成前向验证的成本，算错了

**前向记账的滞后等于持有期，不是一年。** T+1 的工具记 5 天就有第一批分，T+5 的 10 天，
T+20 的 25 天。只有 T+120 的长线工具才真的要等半年。

刚才用库里已有的 16 天决策台记录，已经打出了第一批 T+1~T+5 的成绩单（见 §四），
没等任何一天。

## 二、回测的完整定义：它不是一件事，是三层

```
        ┌──────────────────────────────────────────────────────────┐
        │  L1 历史回测   判据能从原始数据重建（K 线、财务、公告）      │
        │                工具：tools/cond_engine.py（已建成）         │
        │                覆盖：均线/量价/形态/动量/波动 类            │
        ├──────────────────────────────────────────────────────────┤
        │  L2 前向记账   判据依赖当期快照（共振卡、质量分、机构持仓、  │
        │                模型预测、新闻情绪）                        │
        │                工具：tools/pillar_forward_score.py（已建成）│
        │                机制：每天存判断 → 到期用真实价格打分        │
        ├──────────────────────────────────────────────────────────┤
        │  L3 条件路由   把 L1 的分段结果 + L2 的滚动成绩，合成        │
        │                「什么行情开哪几个筛子」                    │
        │                工具：待建（这是「会用」的载体）             │
        └──────────────────────────────────────────────────────────┘
```

**我过去只建了 L1 的一半，然后拿它去否定 L2 和 L3 才能回答的问题。**

## 三、方案主体：一张台账 + 三条流水线 + 一个路由

### 3.1 工具台账（Tool Ledger）——「会用」的前提

现在 31 个工具在库里只有名字和一句话说明。要能用，每个工具必须填满 6 个字段。
**填不满的不许上线。**

| 字段 | 含义 | 谁来填 |
|---|---|---|
| `role` | 选股 / 排除 / 描述 / 排序 | 我定，按代码逻辑 |
| `pool` | 前置池：它在什么范围内工作 | 我定 |
| `horizon` | 持有期（由工具结构决定，不是拍的） | 我定 |
| `regime` | 适用行情（从分段结果反推；未知就写「待定」） | L1/L3 填 |
| `criterion` | 验收标准（按角色四选一） | 我定 |
| `verdict` | 已验证正 / 已验证负 / 无信息 / 反向 / 待定 | 数据填 |

台账落地在 `tool_registry` 表，加 4 列（`role / regime / criterion / verdict`）。
**这张表就是筛台的开关**：`verdict='反向'` 的工具，界面上不能再当「筛子」卖，
要么标成「避开条件」，要么下架。

### 3.2 三条流水线

**P1 · 历史回测（已在跑）**

- 现状：14 个工具 / 39 个单元已测完（`docs/工具条件化回测_第一批报告.md`）
- 待补：6 个纯 K 线工具（tv_platform / tv_wbottom / tv_macd_div / tv_shrink_pull / db_wave / db_chan）
- **新增：把你之前沉淀的那批形态做成插件**——见 §3.3，这是「自己沉淀的没用上」的正面回答

**P2 · 前向记账（今天开始，不改判据只加记录）**

三件事，都很小：

1. **每日快照**：15:30 收盘后，把当天所有产出的判断（pillar_item、共振卡、风险卡、
   质量分、Kronos）连同日期存一份不可变记录。现在这些表要么只存最新、要么只留了几天。
2. **到期打分**：每天开盘前，把所有「到期」的判断用真实价格打分（跑 `pillar_forward_score.py`）。
3. **回写台账**：把滚动成绩写回 `verdict`。**每个工具上线 20 个交易日内必须出第一份成绩单**，
   没成绩单的自动降为「观察中」，不能作为筛票依据。

这一层的关键是：**它是自动的，不需要人去点。** 现在的问题是「工具在那儿，没人用」——
流水线的意思是让判断自己进流程、自己被打分。

**P3 · 条件路由（「什么行情用什么」）**

已有数据就能做第一版，不需要等：

- 输入：L1 每个工具的**分段结果**（每个工具已存 6 段，逐段有边缘值 + 同期大盘涨跌）
- 方法：按「同期大盘涨跌 + 波动率」把 6 段归成 3~4 种行情状态，看每个工具在哪种状态下为正
- 输出：一张表 `行情状态 → 该开的工具（方向/持有期/依据 t 值）`

这张表就是「会用」。产品上的落点：筛台顶部放一个「今日行情」判断，
自动把不符合当前状态的工具置灰或折叠——**不是让人从 31 个里自己挑。**

### 3.3 把「自己沉淀的方法」变成可插拔的判据库

你说得对：金叉、豆包沉淀的那套方法，我一个都没在用。原因是我把每个工具都当成
「要单独写一遍接线」的活，所以永远只做新的、不做旧的。

**改法**：建 `viewer/playbook.py`，统一接口：

```python
def judge(X: dict, params: dict) -> np.ndarray[bool]:
    """X 里是 price/volume/全部指标；返回逐日布尔数组。"""
```

登记即回测：任何方法写进 `PLAYBOOK` 字典，跑一次 `cond_engine.py` 就有池内区分力 +
分段结果 + 前向待打分。**新增一个方法从「半天接线」变成「写 3 行判据」。**

第一批要补进去的（都是能从 K 线重建的，之前全缺）：
- 金叉：MA5 上穿 MA20 / MA10 上穿 MA60、MACD 金叉（DIF 上穿 DEA）、KDJ 金叉（K 上穿 D）
- 布林：站上中轨 / 突破上轨 / 开口放大
- 均线粘合后发散（你提过的「粘合」形态）
- 缺口：向上跳空未回补
- 缩量回踩均线（已有 tv_shrink_pull，但要和 oss_pullback_ma20 的**上下方口径**分清）
- 连板与首板、量价背离

## 七、必须说清楚：有一部分永远回测不了

不是所有工具都能拿到确定结论，这类要认，但不能因此不用：

- **依赖当期不可复现信息**：新闻情绪、公告解读、机构持仓的实时变化。快照存下来之后
  能前向验证，但历史那一段永远补不回来。
- **依赖模型输出**：Kronos 这类，历史预测没存就是没存。
- **样本本质不足**：T+120 的长线工具，即使 15 年历史也只有 30 个独立样本，
  结论永远带误差条。**这类工具的用法应该是「小仓位 + 长跟踪」，不是「等它显著」。**

**关键区别**：以前我把「不能确定」当成「不能用」。正确的处置是
**给不确定的工具定一个「最小可接受证据 + 仓位上限」**，而不是弃用或瞎用。

## 八、这套方案怎么自证有效（验收标准）

不是「做完了」，而是这三个数要动：

1. **每个工具的 `verdict` 从「待定」变成有值**：31 个里至少 25 个在 30 天内落定。
2. **每次开筛子前，能回答「为什么是这几个」**：路由表覆盖率 = 当天被启用工具数 / 总工具数，
   且有 regime 依据的比例。
3. **决策台滚动成绩单胜率变化**：现在 T+5 是 42.7%。如果按 T+1~T+2 的用法调整后仍不改善，
   说明问题不在用法而在判据本身——那时候才有资格说「这套判据要换」。

## 附录：L3 路由表 v0 已跑完（2026-11-05 当天），结果否掉了我自己的假设

`tools/route_table.py`：把 L1 每个（工具×持有期）的 6 段结果，按该段全市场等权**年化**收益
归成上涨（>+15%/年）/ 震荡 / 下跌（<−15%/年），再看每个工具在哪种行情下为正。

79 个（工具 × 持有期 × 行情）组合的结果：

| 项 | 数 |
|---|---|
| 总组合 | 79 |
| 平均边缘为正 | **12** |
| 正的且同号 ≥2/3（稳定） | 10 |
| 正的里面最大 | **+0.383pp**（`oss_reversal20` T+20 @震荡，仅 2 段） |

**那 8 个反向工具，在三种行情下全部为负，而且同号比例更高（3/3、4/4）。**
也就是说它们的负不是"某种行情下的意外"，是持续的方向。

### 这条为什么重要

我原本留的后路是：「平均 0 也许只是无条件化的问题，条件化之后能找到可用窗口」。
**实测把这条后路封了。** 所以对那 8 个工具的处置只能是「降级/反转」，
不能再有"换个时候再用"这种说法——那正是"找理由不用"的另一种形式。

### 唯一有价值的线索

正的窗口全部落在原来判为「≈0」的那 4 个描述器上，且都极小：

| 工具 | 持有 | 行情 | 边缘 | 段数 | 同号 |
|---|---|---|---|---|---|
| oss_reversal20 | T+20 | 震荡 | **+0.383pp** | 2 | 2/2 |
| oss_near_high | T+20 | 下跌 | +0.275pp | 2 | 2/2 |
| oss_reversal20 | T+5 | 上涨 | +0.189pp | 3 | 2/3 |
| oss_pullback_ma20 | T+3 | 震荡 | +0.053pp | 4 | 3/4 |

最大那个 0.383pp 只比一次往返成本（0.25%）多一点，且只有 2 段支撑。
**够不上"可用"，只能当"值得继续跟踪的线索"**——所以它们进 `verdict='待定'`，不降级也不上线。

### 路由层真正的用法

路由表 v0 的价值不是"找到赚钱组合"，而是**给出了一张「哪些组合连方向都没有」的黑名单**，
31 个工具第一次有了「在什么行情下不该开」的依据。这比"不知道该不该开"强一档。

第二版要加第二个维度（波动率），并把 L2 的滚动成绩并进来——那时它才开始有正面用法。
