## 一、结论速览

**「此前列出的来源」确实存在，但它从未进入抓取配置。** 三类原因性质完全不同，不能混为一谈：

| # | 原因 | 涉及来源数 | 性质 |
|---|---|---|---|
| ① | **配置遗漏**（清单里有、程序里没有） | **35 个** | 主因 —— 不是"抓了没展示"，是**没写** |
| ② | **抓了但没解析出**（淘股吧 | 1 个 | 未登录 → 解析 0 条 |
| ③ | **抓了但没进对应板块**（同花顺） | 1 个 | 数据落在海外表，A 股板块看不到 |

**不是"数据源查找失败"**：接口无报错，`refresh_status` 中没有任何 `status='error'` 记录。

## 二、先说一个事实：「此前列出的来源」在哪

用户所指的清单是这两份文件（**均在工作区根目录，不在程序配置里**）：

| 文件 | 内容 |
|---|---|
| `股票投资垂直社区平台清单_整合版.html`（38 KB） | 前五节共 **37 个可抓取平台**：综合股吧 / 技术论坛 / 百度贴吧 / 官方互动 / 财经新媒体 |
| `stock-forum-scraper/tools/_patch_list.py` | 给上面那份 HTML 打补丁的脚本（说明清单由此处生成/维护） |

> **关键**：这份清单**从未反向同步进 `config/sites.yaml`**。清单是"调研文档"，
> 配置是"抓取注册表"，两者之间没有联动机制 —— 这是本次问题的结构性根因。

## 三、三层核对（逐层给证据）

### L1 声明层：`config/sites.yaml`

- `sites:` 段下**只注册了 `taoguba` 一个站点**。
- `player_pool.platforms` 里写了 4 个平台（`taoguba` / `eastmoney` / `xueqiu` / `ths`），
  **但那是"候选来源权重表"，不参与抓取** —— 只有 `sites:` + 解析器注册才决定实际抓取。

### L2 能力层：代码里有没有适配器

```
ingest.py  →  PARSER_REGISTRY = {"taoguba": TaogubaParser}      # 只有淘股吧
overseas/  →  FETCHERS = {rss, html, youtube_api, reddit_json,
                          google_news_rss, xueqiu_json,
                          github_trending, peertube, relay_json}  # 无 tieba / 无互动易
```

### L3 事实层：数据库里真正抓到了什么

| 表 | 总行数 | 示例（`example.local` 占位） | **真实** |
|---|---|---|---|
| `raw_pages` | 234 | 1 | **233**（全部 taoguba） |
| `news` | 11 | 3 | **8**（taoguba） |
| `overseas_news` | 700 | 41 | **659**（约 30 个海外源 + ths） |
| `posts` | 185 | 185 | **0** |
| `trades` | 46 | 46 | **0** |

**真实抓取成功过的来源只有三类**：
1. `taoguba` —— 233 页真实存档
2. `ths`（同花顺）—— 12 条真实新闻（`news.10jqka.com.cn`）
3. 约 30 个海外 RSS/HTML 源 —— 659 条真实新闻

> 界面上看到的"东财 / 雪球 / 同花顺 4 平台"，**全部来自 `demo_data.py` 合成数据**。
> 这一点 UI 已用「示例」角标如实标注，但容易被误读成"抓到了 4 个平台"。

## 四、逐项回答用户的四种猜测

| 猜测 | 判定 | 依据 |
|---|---|---|
| 数据源查找失败？ | **否** | 无任何 `status='error'`；这些来源是**根本没有记录**，不是"有记录读不出" |
| 数据源缺失？ | **是（主因）** | 37 个平台里 35 个在代码中查无域名/适配器 |
| 刷新条件不满足？ | **部分是** | 淘股吧行超时是真的（「实时刷新」默认未勾选，需手动触发） |
| 权限/配置限制？ | **部分是** | 淘股吧 `login_status = login_failed`（无有效 Cookie）；东财/雪球被反爬/WAF 拦截 |

## 五、淘股吧为什么抓回来却没数据（原因②细查）

```
网络层：通
  raw_pages 233 页真实存档（首页 93 KB / 实盘话题页 121 KB）

解析层：产出 0
  meta[last_ingest] = raw_pages=3, news=4,
                      trades=0, posts=0, players=0, positions=0

原因：未登录
  login_status = login_failed
  detail = "站点 淘股吧 未配置可用的表单登录地址（login_url），且本机无有效 Cookie。
            请执行 credentials add-cookie。"
  选手主页 /user/XXX 仅返回 3725 字节 = 登录跳转页，不是真实主页
```

**结论**：抓取器工作正常，卡在**登录态**。补上有效 Cookie 后，`players` / `positions`
才有望产出真实数据 —— 这是投入产出比最高的一步。

## 六、整改方向（按性价比排序）

| 优先级 | 动作 | 预期收益 | 前置条件 |
|---|---|---|---|
| **P0** | 补淘股吧 Cookie（`credentials add-cookie`） | 打通 `players`/`positions`/`trades`/`posts` 四条真实数据链 | 用户本机浏览器登录一次 |
| **P0** | **建立"清单 → 配置"的同步机制**，杜绝清单与配置再次脱节 | 结构性止血：以后加来源不再遗漏 | 无 |
| **P1** | 同花顺数据接入 A 股舆情/实盘板块（现仅落海外表） | 复用已有真实数据，零抓取成本 | 无 |
| **P1** | 东财股吧 / 雪球：接浏览器渲染或有效 Cookie 后启用 | 4 平台共识基数变成真的 | 反爬绕过方案 |
| **P2** | 百度贴吧（公开页面，`tieba` 适配器需新写） | 补上散户情绪最大流量池 | 需确认 robots/合规边界 |
| **P3** | 新浪/大智慧/金融界/中金在线/理想论坛等 26 个平台 | 长尾覆盖 | 逐个写适配器，建议按流量分批 |

### 合规提醒
项目已有 `scraper/compliance.py` 且 `respect_robots: true`。
新增来源必须沿用该约束，**不绕过 robots、不代注册账号**。

## 七、审计方法（可复用）

```bash
# 平台清单 × 配置 × 适配器 × 真实数据 四层交叉核对
python tools/audit_declared_sources.py
```

脚本的两条硬规则（本轮踩坑后加的）：

1. **真实数据与示例数据必须分开统计** —— 否则 demo 里带了 4 个平台名，
   会被误判成"真抓过 4 个平台"。
2. **判据只用真实域名 / 适配器键名，不用中文泛称** —— 否则「贴吧」二字
   出现在模块 docstring（`scraper/__init__.py` 第 1 行）里，会被误判成"已有适配器"。
