# 博主荐股全线下线 + 定时任务停摆（2026-10-30）

> 进哥原话：「荐股类的这些博主以后不关注了，就不需要这些信息的情况下他们噪声。情绪有很多地方都可以搜集得到，之前那些博主的舆论已经够用了。定时任务关于个股的推荐是不是也可以停了，就直接给它删掉就可以了。」

上一轮（10-29）删的是**展示层三页**。这一轮把**采集层和打分层**一并停掉。
到此，博主荐股这条线在设计上已无任何活口，只剩历史数据供风控使用。

## 一、先回答「为什么我这边还是旧界面」

两个原因叠加，都已修：

1. **前端版本号没跟着加**（主因）。
   `viewer/static/index.html` 里 `app.js?v=` 是缓存开关。10-29 改了 1400 行 JS 却没动版本号，
   浏览器直接吃缓存旧文件 —— 项目注释里 10-01 就踩过同一个坑，这次又踩了。
   → 已改 `20261029-aireview5` → **`20261030-noblogger1`**（`app.css` / `funnel.js` / `<meta app-version>` 四处同步）。
2. **「博主共振」本来就还在**。它是「今日总览」下的子 tab，不属上一轮删的「博主荐股/参赛股/外部荐股验证」三页。
   → 本轮已改名 **「多源共振」** 并摘掉博主维度。

> 现在页面每 60 秒跟 `/api/version` 比一次版本，不一致会在顶部弹「界面已更新，点此刷新」。
> 若仍看到旧界面，`Ctrl+F5` 硬刷一次即可。

## 三、共振面板：「博主共振」→「多源共振」

**关键判断：不能整页删。** 这个面板三支柱里，B「战法体系」是你明确要留的**技法成果**
（86 个技术战法回测档案 + 268 个技法知识图谱节点）。整页删会把技法一起删掉。

| 支柱 | 处理 | 现在 |
|---|---|---|
| A 个股共振 | 摘掉博主维度 | 120 张卡，权重只剩战法/舆情/引擎 |
| B 战法体系 | **完整保留** | 86 个战法 + 268 个图谱节点 |
| C 信源画像 | 博主行自然消失（从信号总线聚合） | 131 → 118 条（86 战法 + 24 龙虎榜席位 + 7 引擎 + 1 舆情） |
| 自我进化 | 保留 | 4 条 |

### 权重怎么处理的

原 `W_BLOGGER = 0.34` → **0**，份额按比例并入其余三项。
但 `evo_weight` 表里历史学出的行仍带 `w_blogger=0.136`，直接用会让三项之和只有 0.864（分数被整体压低 13.6%），
且页面还显示「博主 13.6%」—— 删了又没删干净。
故新增 `_drop_blogger()`，在**读权重这一处统一收口**：无论来自 evolve 还是默认，博主一律归 0 并重归一化。

实测权重（来自 10-22 的进化结果，剔除博主后重归一）：

| 维度 | 原 | 现 |
|---|---|---|
| 博主 | 13.6% | **0**（下线） |
| 战法 | 13.6% | **15.7%** |
| 论坛舆情 | 65.6% | **75.9%** |
| 主引擎交叉 | 7.2% | **8.3%** |

### 一条刺眼的证据

`evo_weight` 的 note 里记着：**blogger t = -15.75，显著**。
负号意味着「博主提及越多的票，T+5 越差」，且显著到 |t| 远超前三位。
这条维度不是"没用"，是**反向有用** —— 留着它等于每张卡都在被一个说反话的维度拉低分。删掉是对的。

### 数据侧的清空

`_pull_blogger()` 改为恒返回 `[]`（**留桩不删函数**，防止后人误加回来，docstring 里写明了三条依据）。
重跑 build 后：

| 项 | 前 | 后 |
|---|---|---|
| 信号总线 `sig_unified` | 4091 条（含 blogger 952） | **2783 条**（lhb 1211 / engine 712 / strategy 691 / sentiment 169） |
| 信源画像 `res_source` | 131 | **118** |
| 战法 `res_strategy` | 86 | **86** ✓ |
| 技法图谱 `kb_strategy_node` | 268 | **268** ✓ |

构建耗时 11.8s，接口 0.59s。

## 五、没动的地方（要你拍板）

1. **概念分支页「④ 谁在说 —— 博主/实盘选手提到过该概念的票」**
   这里混着**实盘选手**（淘股吧交割单、雪球组合、集思录晒盘），跟你说的「荐股博主」不是一类。
   删掉会连实盘覆盖一起没。当前保留。

2. **候选池的「博主反向警示」overlay**（`server.py` 4 处读 `blogger_overlap`）
   它是「很多人同时念叨 + 历史负收益 → 标风险」，方向和你判断一致，且不展示"谁推的"。当前保留。

3. **剔除池 `tools/build_exclusion.py`**
   用 `blogger_overlap` 把「博主推过且实证 T+5 平均 -3.33%（577 跌 / 250 涨）」的票剔出干净宇宙。
   这是**负面证据的风控应用**，删了反而丢依据。数据冻结在 10-29，作为历史证据仍有效。

4. **`predictor_daily`（每日预测）** —— 主引擎自己的选股，不是博主推荐。**没停**。
   你说的「个股推荐的定时任务」如果也包括它，说一声我再停。
