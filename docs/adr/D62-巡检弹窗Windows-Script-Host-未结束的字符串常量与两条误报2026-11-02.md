## D62 · 巡检弹窗：「Windows Script Host 未结束的字符串常量」与两条误报（2026-11-02）

**现象**：桌面每隔 6 小时弹两个 `Windows Script Host` 错误框，内容固定为
`脚本 C:\Users\...\Temp\wb_viewer_alert.vbs / 行 1 / 字符 13 / 未结束的字符串常量 / 800A0409`。
进哥反馈「最近老弹这个」。

**根因（两个独立问题叠在同一个弹窗上）**：

1. **VBScript 字面量跨行**。`popup_alert()` 把 `f"{level}\n\n{msg}\n\n（…）"` 整段拼进
   `MsgBox "<这里>"`。VBScript 的字符串字面量**不允许换行**，解析到第一个 CR 即报
   800A0409。位置 `行1 字符13` 精确对得上：`MsgBox "WARN` 共 12 字符，第 13 个就是那个回车
   —— 说明文件本身是 UTF-16 且被正确解码，坏的只有换行。**这个弹窗从来没能显示过告警内容，
   一直是错误框。**
2. **集中度规则没有适用前提**。`trades` 表实测只有 24 条、4 个标的，`Top5` 按定义恒为 100%、
   `Top1` 轻易越过 30%，于是每轮必中 `conc_ceil(CRITICAL)` + `conc_drift(WARN)` 两条。
   这不是「数据异常」，是小样本下指标无定义。两条告警 → 两个错误框，
   而计划任务实测是**每 2 小时**触发一次 → 每天 8 个 Script Host 错误框。

**修法**：

- `popup_alert()` 重写：消息正文写进独立 `.msg`（UTF-16），VBS 只做固定六行
  （`GetParentFolderName` → `BuildPath` → `OpenTextFile(-1)` → `ReadAll` → `MsgBox`）。
  **消息内容不再进入任何代码字面量**，换行/引号/反斜杠/中文都不再是问题。
  文件名带 `pid_时间戳`（旧版固定文件名，存在「一个进程正在写、另一个 wscript 正在读」的截断风险），
  并顺手清理 1 小时前的遗留文件。启动参数加 `//B`（batch 模式，抑制脚本错误对话框）：
  **今后即使脚本本身还有问题，也只会静默失败，绝不会再糊一个 Script Host 错误框到屏幕上。**
- 新增 `conc_usable(stats)` 闸门：`total < 100` 或 `n_symbols ≤ 5` 时**不判集中度**，
  并在巡检摘要里如实写明「本轮不判：样本量 24 < 100」。样本不够宁可不判断，也不许乱报。
- `_get()` 加 `tries/gap` 重试，`/api/scheduler/status` 用 5 次 × 4s：后端重启（改代码 reload、
  守护进程拉起）约 10~30s，旧版一次连不上就判「服务不可达」并弹 ERROR，等于把运维动作误报成线上故障。
- 规则 2 重写（两处结论性错误）：
  · 顶层 `last_ok_at` 需要**全部源成功**才推进，实测 6 个源里 5 个正常、只因 taoguba
    Cookie 过期就报「数据已 97.2h 未更新」—— 结论是错的。改为按**最鲜的源**判断。
  · 更根本的：这套分源刷新是**手动触发**的（用户点「抓取并更新」），而自动调度器
    `/api/scheduler/status` 明确 `sources_empty` / `skip_reason=sources_empty`，
    即"没有任何自动任务在跑"。**对一个没有自动任务的数据源，用「多久没更新」去报警，
    等于拿用户没点按钮当故障** —— 每 2 小时弹一次，永远弹下去。
    因此 `stale` 与 `source_error` 都只在 `auto_on`（调度器已启用且有信源）时成立；
    不成立时在巡检日志里如实写「本轮不做陈旧判定」，**不是静默关掉**。
  · `stale` 与 `source_error` 互斥，判的是**当前状态**而非「本轮报没报」——
    否则 stale 被去重压住的那一轮，source_error 会钻空子补弹，等于换个顺序继续骚扰。
- 新增 `python viewer/check_fetcher_health.py --test-popup`：一条命令手动验证弹窗能正常显示。

**验证**：`tests/test_health_alert.py` 11 条（逐行字面量闭合 / 正文不得进代码 / UTF-16 BOM /
`//B` / 异常不抛 / 小样本不报警 / 无自动任务不报陈旧 / 全停时不再补弹单源 / 单源坏必须点名）。
干跑实测：同一份生产数据，旧逻辑 2 条告警（换新脚本后仍会 1 条），新逻辑 **0 条**，
日志写明「集中度本轮不判：样本量 24 < 100」「自动调度器无信源→本轮不做陈旧判定」。
计划任务实测为**每 2 小时**触发（非 6 小时），旧逻辑等于每天 8 个错误框。

**诚实边界**：本机安全策略禁止命令行直接执行 `wscript/cscript`，因此 VBS 只能做**静态**校验
（结构、编码、字面量闭合），未能主动实跑。间接证据：10:53:19 计划任务用新代码跑过一次，
生成了 `.msg`+`.vbs` 对且进程已正常退出。若日后仍见该错误框，说明本机 Script Host 层另有问题，
应改用非 Script Host 的弹窗通道（本机两个 Python 都没有 tkinter），而不是再调这段脚本。
