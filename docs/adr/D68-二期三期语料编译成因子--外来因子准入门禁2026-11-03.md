## D68 · 二期三期：语料编译成因子 + 外来因子准入门禁（2026-11-03）

**背景**：D67 把 14 个已有能力装进了工具货架，但货架上全是「读现成结论」。进哥原话是
「技术价值教学啊、豆包技术方法呀这些其实都是有价值的，你能不能把这些也都从现有能力当中
拆出来，都拆成各种各样的工具」——这些方法论**当初只是文本**，没有一行代码。二期把它们
编译成能算的因子；三期解决"以后从外面搬进来的东西怎么保证不把系统搞乱"。

**二期做法（`viewer/factors.py`，6 个因子）**

| 因子 | 来源 | 判据要点 | 全市场实测 |
|---|---|---|---|
| `tv_shrink_pull` 缩量回踩 | B站语料 | 站上MA20+MA20向上+踩到MA20±3%+5日均量≤前20日的75% | 5264 → **6** |
| `tv_wbottom` 双底(W) | B站语料 | 90日两底价差≤5%、间隔≥15日、中间反弹≥8%+两条结构约束 | 5264 → **488** |
| `tv_platform` 平台突破 | B站语料 | 破前60日振幅≤25%+近10日≤8%+破20日高+量≥1.5倍 | 5264 → **21** |
| `tv_macd_div` MACD底背离 | B站语料 | 两低点：价创新低但DIF抬高+现价离低点≤8%+DIF今日不跌 | 5264 → **293** |
| `db_wave` 波浪位置 | 豆包语料 | 二浪=先涨≥25%后回撤30~55%；三浪=调过≥15%后站上前高98% | 5264 → **521** |
| `db_chan` 缠论中枢 | 豆包语料 | 60日25~75分位当上下沿+高度≤15%+离下沿≥2%+末次下探守住 | 5264 → **44** |

**三个被数据推翻的第一版判据（这是这一节最该看的部分）**

1. **`tv_macd_div` 第一版跑出 0 只**。判据是「今日收盘是 60 日最低 + DIF 距窗口最低有 2% 价距
   + DIF 连抬 3 日」。问题不是市场没有背离，是**判据自相矛盾**：「今日创 60 日新低」意味着
   今天在跌，「DIF 连抬三日」意味着今天在涨。实测当日 318 只创 60 日新低，其中 DIF 能连抬
   三日的只有 **2 只**，交集必然为 0。改成比较「两个价格低点」（后者价更低、但 DIF 更高）
   之后才是教科书里的那个东西 → 293 只。
   **教训：「0 只」有时不是市场干净，是判据写错了。以后见到 0 先怀疑代码，再怀疑数据。**
2. **`tv_wbottom` 第一版 1117 只（21%）等于没筛**。只判「两底价差 + 中间反弹」，
   而**下跌中继也会造出两个相近低点**。加两条结构约束（MA20 不得低于 MA60 的 98%、
   现价须离开第二底 2% 以上）→ 488 只。W 底的前提是"下跌停住了"，不是"跌出两个坑"。
3. **`db_wave` 第一版 1804 只（34%）**。用「回撤幅度 + 60 日涨幅 + 分位」三个数，
   这描述的是**现在长什么样**，不是**浪走到哪儿**——普涨日里 60 日涨 15%~45% 且贴着
   250 日高的票满街都是。加两个**顺序**约束（低点须在高点之前＝先涨后回；中途须调过
   ≥15%＝真有二浪）→ 521 只。**判形态必须判顺序，不能只判截面上的数**。

**口径纪律（不许违反）**：调阈值**不能凭当天行情**。2026-11-03 上涨家数占 84.6%、中位 +2.07%，
是异常普涨日，按当天调必然过拟合。阈值只能由**规则本身的内在合理性**定（如"W 底要求两底
等高"、"三浪要求中途调过"），跑出来的数只是结果，不是目标。

**三期做法（`viewer/factor_import.py`）**

- **表达式 DSL**：`close/ma(close,20)-1` 这类式子经 `ast` **白名单**校验（只允许四则运算与
  12 个白名单函数，禁属性访问/下标/lambda/import），不用裸 `eval`。外来字符串一律先过白名单。
- **IC 自己算，不抄仓库数**：截面 Rank IC（Spearman），250 个交易日逐日算 → IC / ICIR / t。
  为什么不用 Pearson：A 股截面极值（涨停、退市前暴跌）太多，Pearson 会被几根极端值带走。
  **不许**引用仓库自带的回测 IC —— 幸存者偏差、未来函数、只挑好行情三段都常见。
- **相关性跟「已知风格」比，不跟我们的布尔因子比**：现有 6 个因子输出 0/1，对 0/1 做
  Spearman 会大面积并列，相关系数没有统计意义。所以拿 8 个经典风格（20/60日动量、
  5日反转、20日波动、量比、均线偏离、成交额、振幅）当对照，这是行业里查"新因子是不是
  旧因子换皮"的标准做法。
- **四条硬线**：`|IC|≥0.02`、`|ICIR|≥0.30`、`|t|≥2.5`、`最高撞车<0.70`、有效 IC 天数 ≥120。
- **三态 + 影子期**：`candidate → shadow`（过了回测）/ `rejected`（没过，**也落库**，
  因为"试过并且知道为什么不行"是资产）/ `active`（影子 20 个交易日仍全过）。
  **影子期不能用回测替代**：回测 IC 好只说明"历史上成立"，影子期验的是"上线之后还成立"。
- **IC 转负自动降权**：`decay_scan` 只看**符号是否翻转**，不看幅度变小 ——
  从 +0.03 掉到 +0.005 只是变弱，从 +0.03 变 −0.03 是**方向反了**，后者意味着照它选股
  会系统性选到反的。

**门禁自检（证明它真的在挡，不是摆设）**

| 喂进去的式子 | 结果 | 判定理由 |
|---|---|---|
| `pct(close,20)` | **拒** | 与「风格·20日动量」相关 **1.00** —— 逐字换皮 |
| `-std(pct(close,1),20)` | **拒** | 撞「风格·20日波动」1.00 + IC 0.006 + t 1.92 |
| `pct(close,20)-pct(vol,20)` | 过 → 影子期 | IC 0.0209 · ICIR 0.41 · t 5.67 · 撞车 0.63 |
| `close/hhv(close,250)-1` | **拒** | ICIR 0.17、t 2.31、撞「均线偏离」0.71 |

自检顺带跑出一个真实市况：近 250 日 **20 日动量的 IC 是 −0.028**（负），
说明这段时间 A 股是**反转市**不是动量市 —— 与"涨得多的后续更容易跌"一致。

**发现（不自动编译，这条边界是刻意的）**

`factor_import.discover()` 复用 `oss_mine.scan_github`（加了 `queries` 参数，不写第二套 HTTP），
5 个因子导向检索词 × 6 条，实测 6.3 秒扫到 14 个仓库，按命中关键词数 × 热度排序，入
`factor_source` 表等人在页面上看。

**为什么不自动把仓库代码编译成因子**：
1. 各仓库复权口径/按股按手/停牌处理全不一样，拿我们的日线去跑别人的式子，IC **假得像真的**；
2. 多数仓库给的是回测框架不是因子定义，从框架里抠因子得读代码、理解意图，这步自动化做不到；
3. 真正的价值在 README 那句"我们这么判断"，不在代码里。方法论要人读 → 写成一行式子 → 过门禁。

所以**发现可以自动，编译必须有人**。扫描器产出的是待办清单，不是因子。

**两处诚实的降级**
- 扫描返回 0 条时记 `verdict='empty'`，页面写「上次没取到（网络或限流），这次的空不代表外面没有」。
  **绝不把"未取到"记成"没有新东西"**。实测就撞到过：连续两次 `--discover --force`，
  第二次因 GitHub 匿名限流（10 次/分钟）返回 0 条。
- 预筛关键词短 ASCII 词必须**整词匹配**：第一版 `ma` 命中了 `market`、`ic` 命中了别的词内部，
  命中数虚高。而命中数是用户判断"先看哪个仓库"的唯一排序依据，虚高就是误导。
  加 `rehint()` 在关键词表变更后重算全表，不让过时数字替用户做决定。

**级联的一个硬发现**：`tv_wbottom → tv_macd_div → db_chan` 实测 `5264 → 488 → 16 → **0**`。
不是数据没票，是三个判据**互相排斥**：W 底要求两底价差 ≤5%（等高）、MACD 背离要求第二个底
更低、缠论中枢要求现价在 60 日 25~75 分位内。三条串起来等于要求一只票同时"在底部、还在创新低、
还在横盘震荡"，逻辑上就不该有票。**级联不是越多越好**，所以预置链只加了两级的两条
（底部确认 5264→488→16、平台真突破 5264→21→5），并在代码里写死注释说明为什么不加三连。

**调度**：`factor_discover` 每日 16:30 触发、**任务内部自节流 7 天**。
为什么不把"每 7 天"写在调度层：项目的调度是「当日未跑就补跑」的日更模型，没有周模型；
节流放进任务里，机器关机几天再开机也不会漏一次，写在调度层会漏。超时 600s（实测 6.3s，11 倍余量）。

**推翻条件**：
- 若 `decay` 状态的因子长期占多数，说明 250 日窗口对因子失效太迟钝，应缩到 60 日滚动；
- 若影子期 20 天里有大量因子"过回测但影子期就翻车"，说明回测窗口与实盘脱节，
  应改为**滚动样本外**（walk-forward）而不是固定 250 日；
- 若`rejected` 里反复出现同一个表达式（有人一直在试同一个换皮因子），说明门禁理由没被读到，
  应把 `gate_note` 直接显示在提交结果里而不是只落库（现已如此）。
