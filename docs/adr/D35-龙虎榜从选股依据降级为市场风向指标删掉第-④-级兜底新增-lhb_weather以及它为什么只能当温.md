## D35 龙虎榜从「选股依据」降级为「市场风向指标」：删掉第 ④ 级兜底、新增 `lhb_weather`、以及「它为什么只能当温度计」（2026-10-30）

### 1. 降级依据：有信息量的是「换手」，不是「上榜」

这不是拍脑袋的产品喜好，是 `viewer/avoid.py` 自己跑出来的（原文见 `viewer/avoid.py:93-99`）：

| 分组 | T+5 按日超额 | t | 样本 |
|---|---|---|---|
| 近 10 日上榜（**不限**换手） | **+0.006%** | **0.07** | 2621 日 / 69.5 万 |
| 上榜 且 换手 < 15% | **+0.881%** | **+10.4** | 40.3 万 |
| 上榜 且 换手 ≥ 15% | **−0.91%** | **−11.28** | 4077 日 / 37.3 万 |

三行连起来看只有一种解读：**「上榜」这个事件本身的信息量是零**（逐样本还是 −0.05%，与 +0.006% 符号冲突），
真正有分辨力的是**换手率**。而且是 `(−1.22%×29.3万 + 0.881%×40.3万) / 69.5万 ≈ −0.05%` 这种
"两档反向、加权后归零"的结构 —— 拿"上榜"当正向信号不是弱，是**方向都不确定**。

所以：**龙虎榜不能再当"这只票值得看"的理由**，只能当"全市场在干什么"的温度计。
本决策只改**用法**，不改抓取、不改调度、不动 `market_regime`。

### 2. `strategy_sim.universe()` 删除第 ④ 级「lhb_stocks 龙虎榜历史兜底」

原四级降级链 ①`stock_liquidity` → ②本地日线 → ③干净宇宙 → ④`lhb_stocks` 历史。
删 ④ 的理由，恰恰是上面那张表：**拿一个 t=0.07 的事件去凑候选池 = 用噪声选股**。
而且它的覆盖只有"历史上过榜的票"，比全市场窄一个数量级 —— 一旦被触发，
页面一切正常、结论全错，属于**最危险的静默降级**：比空池报错坏得多。

现在 ③ 之后若仍空，直接 `return [], names, {}` 并打印错误（`strategy_sim.py:1588-1591`）。

**③ `clean_universe` 什么情况下会空**（lead 要求必须回答，量化见下表，取数自 `app.db`）：

| 环节 | 实况 | 空的条件 |
|---|---|---|
| `stock_names` 全表 | 5588 行，脏 code 0 条 | 表被清空 / 读失败 |
| `all_ashares()`（首位 0/3/6/8/9） | 5585（0:1495, 3:1410, 6:2330, 8:2, 9:348） | — |
| `_keep()`（首位只留 0/3/6） | **5235**（砍掉 8/9 共 350 只） | 全表都是 8/9 开头 |
| 减去 `exclusion_pool`（224 条，st 210 / no_kline 14，其中命中 0/3/6 的 214 条） | **5021** | 剔除池吃掉全部 5235 只 |

**结论：③ 现实中不会"自然空"，唯一的空法是 `stock_names` 读失败被静默吞掉。**
`viewer/universe_filter.py:141-143` 的写法是

```python
try:    rows = con.execute("SELECT code FROM stock_names").fetchall()
except Exception: rows = []        # ← 异常 → 空列表 → all_ashares() = []
```

`app.db` 被长任务写住时（本环境连 `mode=ro` 都打不开，见 §7），这句会等满 `timeout=30` 再抛
`OperationalError`，然后被吞成 `[]`，`all_ashares()` 返回空 → ③ 空。删掉 ④ 之后这条路径的终点
就是那句错误打印 + 空池，**调用方会看到"池子 0 只"而不是一份看不出错的假名单**。
这就是删 ④ 与"空池告警"必须成对做的原因：删了兜底却没告警，等于把静默降级换成了静默崩溃。

### 3. 四维样本现实：两维能定档，两维只能存值

`viewer/lhb_weather.py` 设计成四个维度，但**能进合成分的只有两个**，因为另外两个的样本只有一个月：

| 维度 | 表 | 实况 | 进合成？ |
|---|---|---|---|
| 参与度 | `lhb_stocks` + 分母 | **4084 日（2010-01-04 ~ 2026-10-30）** | ✅ 权重 0.5 |
| 赚钱效应 | `lhb_stocks.d1_chg` | **同上（lag 1 后 4083 日非空）** | ✅ 权重 0.5 |
| 结构（机构/游资占比） | `lhb_inst` / `lhb_depts` | **27 日（2026-09-16 ~ 2026-10-30）** | ❌ 只存值 |
| 集中度（top3/HHI） | `lhb_sector_focus` | **25 日（2026-09-16 ~ 2026-10-28）** | ❌ 只存值 |

用 `sample_days_structure` / `sample_days_sector` 两个字段把"我只有几天样本"**写进表里**，
配 `MIN_SAMPLE_FOR_STATE = 250`（≈一年交易日）这个开关：样本不足一交易日年，该维度不许影响 `state`。
**开关不写死成 26/25** —— 那等于把今天的临时现状刻成永久契约，回补跑起来之后代码会继续无视新数据。
250 的理由：一年才够覆盖一次完整的"政策底—情绪顶"循环，少于一年算出来的分位是噪声定位。

单测 `test_short_sample_dims_never_change_state` 把这条钉住：同一份 `lhb_stocks`、
结构与集中度**符号和量级全部反过来**，`score` / `state` 逐行必须完全一致。

### 4. 前视偏差：`d1_chg` 必须 lag 一个交易日

`lhb_stocks.d1_chg` 是"上榜**次日**涨跌幅"。算 d 日的赚钱效应，只能用到 `trade_date <= d-1` 的样本；
当天上榜的票 `d1_chg` 还是 NULL（2026-10-29 实测全 NULL），但**第二天回填后**，如果不 lag，
d 日那一行的 `d1_mean_20` 就会混进"d 日上榜票的 d+1 收益" —— 用未来算现在。

实现是 `shift(1)` 再 `rolling(20)`（`lhb_weather.py:317-321`），红绿对照实测：

| 版本 | d1 日 | d2 日 | d3 日 |
|---|---|---|---|
| 无 lag（红） | 15.0000 | **343.3333** ← 混进了 d2 当天的 1000 | 343.3333 |
| 有 lag（绿） | nan | **15.0000** ← 只用 d1 样本 | 343.3333 |

这个 bug 不会报错、不会让图变形，只会让回测曲线"变好看一点"，是最难靠肉眼发现的一类。

### 5. 回测：按事先写死的判据**通过**，但「pooled 正 / 滚动负」是尺度问题、不是矛盾

`python -m viewer.lhb_weather --backtest` 实数（4084 上榜日，可定档 4022，有前瞻收益的 3962）：

| 档位 | N | T+1 均值 | 胜率 | T+5 均值 | 胜率 |
|---|---|---|---|---|---|
| hot | 1409 | +0.155% | 58.8% | **+0.722%** | 60.9% |
| neutral | 1238 | +0.082% | 54.9% | +0.373% | 57.1% |
| cold | 1311 | −0.035% | 53.0% | **−0.051%** | 51.1% |
| hot−cold | | +0.190% (t=+2.68) | | **+0.773% (t=+4.61)** | |

三段：2010-2015 +1.008 / +0.838 / +0.011（t=+2.68）；2016-2020 +0.554 / −0.039 / −0.020（t=+2.33，
**唯一非单调的一段**，neutral 略低于 cold）；2021-2026 +0.603 / +0.258 / −0.134（t=+3.19）。
子维度：赚钱效应单独 hot +0.733 / neutral +0.399 / cold −0.074（单调、跨度最大）；
参与度 hot +0.661 / neutral +0.220 / cold +0.182（T+5 端几乎贴平，信号主要来自赚钱效应）。

**`verdict()` 输出"通过"。但 ② 那对矛盾必须先解释清楚，否则这个"通过"没有意义：**

| 口径 | vs fw5 |
|---|---|
| 全样本 Spearman | **+0.1029**（n=4018） |
| 滚动 60 日 IC 均值 | **−0.0158**，名义 t=−5.08 |

逐条排除（`_probe_ic.py` + `_probe_scale.py`）：

1. **不是重叠样本放大的假阳性**。fw5 每 5 天取 1 个、切 5 个互不重叠子样本：
   +0.1036 / +0.1339 / +0.1250 / +0.0889 / +0.0655，均值 **+0.1034**，与重叠版 +0.1029 几乎相同。
   分块 bootstrap（block=5，1000 次）95% CI **[+0.0516, +0.1536]**，P(IC>0)=**1.000**。
2. **名义 t 是假的，但假在哪边要说清**。滚动 60 日 IC 序列 lag1 自相关 **+0.990**（相邻窗共享 59/60 天），
   按 AR(1) 折算有效样本 4014 → **≈21**，修正后 t≈**−0.37**；Newey-West（lag=60）t=**−0.88**。
   同理 fw1 那个 t=+3.64 也不可信（NW t=+0.56）。**两个名义 t 都得作废，符号相反的两个数都不显著。**
3. **正相关的来源是"尺度"，不是 2010-2015**。窗口长度扫描（滚动 IC 均值）：

   | 窗口 | 20 日 | 40 日 | 60 日 | 120 日 | 250 日 | 500 日 |
   |---|---|---|---|---|---|---|
   | mean IC vs fw5 | −0.0904 | −0.0529 | **−0.0150** | +0.0388 | +0.0689 | +0.0856 |
   | 负窗口占比 | 62.3% | 59.5% | 54.0% | 37.5% | 17.6% | 6.1% |

   **单调抬升、穿过零点。** 60 日窗恰好落在零点附近 —— 这就是"−0.0158"的全部含义：
   score 是 20 日均值再取 250 日分位，天生是慢变量；60 日窗里它动得太少、5 日噪声太多。
   信息只存在于**多月尺度**，pooled 全样本 ≈ 长窗端，所以是 +0.10。
4. **不是纯水平效应（Simpson）**。年内秩 pooled：fw5 **+0.0606**、fw1 **+0.0431**，
   与逐年 IC 的等权均值（+0.0603 / +0.0440）对得上；17 年里 fw5 有 **12 年**为正。
   跨年 `mean(score)` vs `mean(fw5)` Spearman +0.7181 确实存在（水平效应贡献约 +0.04），
   但去掉年效应之后仍有 +0.06，不是全靠它。
5. **高频是负的**。`Spearman(Δscore, Δfw5) = −0.0292`、`Spearman(Δscore, fw5) = +0.0146` ——
   score 的**变化**对未来收益没有预测力，甚至轻微反向（短周期均值回复）。

**确定解释**：两个数都对，只是量的不是一个东西。`+0.1029` 是"多月尺度上的水平关联"（真实、bootstrap 支持），
`−0.0158` 是"60 日尺度上无关联"（真值≈0，名义 t=−5.08 是 0.99 自相关造出来的伪重复）。
**跨尺度比较得出"矛盾"，是统计口径错配，不是数据错。** 结论会影响用法，见 §6。

硬判据 `hot−cold` 也做了一次诚实版（分块 bootstrap，block=5，2000 次）：
fw5 **+0.7733%，95% CI [+0.2359%, +1.3213%]，P(>0)=0.998**（等效 t≈2.8）；fw1 +0.1902%，CI [+0.0421%, +0.3432%]，P=0.997。
**所以"通过"这个结论站得住**，只是强度比名义 t=4.61 弱一档。

### 6. 边界：不用它做个股择时（这是降级的落地约束）

1. **标的错**。回测的目标变量是 `market_daily()` 算的**全市场等权日收益**，不是个股收益。
   它对"明天大盘好不好"有弱信息，对"买哪只"零信息。
2. **频率错**。§5 第 3 条：60 日尺度真值≈0，日频调仓等于拿噪声当信号。
   可用的是"这几个月市场在升温/降温"，即**给仓位/风偏一个背景值**，不是给买卖点。
3. **样本薄**。4022 个可定档日看着不少，但独立信息量受慢变量限制（§5 第 2 条），
   折算后相当于二十来个独立观测；三段里还有一段（2016-2020）不单调。
4. **`state` 只由参与度+赚钱效应决定**。结构与集中度只有 27/25 天，`MIN_SAMPLE_FOR_STATE=250`
   一天都还没到，任何"机构占比高所以如何"的说法目前都是**没有样本支撑的**。

一句话：**它是温度计，不是方向盘。** 展示可以，进个股判定不行；将来结构与集中度攒够 250 天，
要重新跑一遍 §5 才谈能不能升格。

2. **`lhb_weather_daily` 表未建**：`compute()` 默认不落库，要 `--save` 才写；本轮没跑 `--save`。
   建表 DDL 已在 `lhb_weather.py::DDL` 里，`save()` 只整表重写自己那张、**不碰 `market_regime`**
   （单测 `test_save_writes_only_own_table` 钉住）。
3. **`app.db` 的读锁比想象中严**：`pillars_daily` / `predictor_daily` 在写时，
   连 `sqlite3.connect('file:...?mode=ro', uri=True)` 都直接 `unable to open database file`
   （不是行锁，是 WAL 的 `-shm` 拿不到）。本轮取证改用 `mode=ro&immutable=1` 读主文件，
   **代价是 WAL 未回放**（主文件里 lhb_stocks 已到 2026-10-30 / 4084 日，与 WAL 口径差 1 天，不影响结论）。
   生产代码 `_ro()` **没有**改成 immutable —— 那会在 WAL 未 checkpoint 时读到旧数据，比报错更坏。
   这条留给阶段二：`lhb_weather` 落库应当在**写完 lhb_daily 之后、闸释放之前**跑完，避免和长任务抢读。
4. **`strategy_sim` 的 ② 本地日线兜底仍可能慢**：`_liquid_from_kline` 扫全库，池子非空时才算，
   不触发降级不会跑；但 `stock_names` 读失败那条路径（§2）目前只有 `print`，没有抛异常，
   调用方若忽略返回值仍可能拿到空池。**是否改成 raise 需要和 `strategy_sim` 的调用方一起看**，本轮未改。
5. **`compute()` 的 verbose 打印标签不准（只影响日志，不影响落库值）**：那句
   `"可定档 %d 天"` 数的是 `score.notna()`=4022，而真正有 `state` 的是 **3962** 天。
   差的 60 天是 2010-04-07 ~ 2010-07-05 —— `roll_thresholds` 需要 60 个历史观测，
   前 60 个有 score 的日期阈值仍是 NaN、`classify` 返回 `unknown`，这是**正确行为**。
   但日志里把它叫"可定档"会让人误以为 4022 天都能定档。**本轮未改**（改输出也要红绿对照，
   优先级低于阶段二）；阶段二接 UI 时一并订正为 `可定档 %d / 有分值 %d`。
