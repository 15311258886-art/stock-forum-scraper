## D66 · 评分日变化 + 准入闸门 + AI 取数独立化（2026-11-03）

进哥三条原话（同一轮）：
1. 「中线名单很多天不变，这个没有问题，但是它每天可能会有起伏，那起伏的过程当中你的评分
   肯定是在变的，对吧？你不能说你股票不变但评分也不变，这就不对了。」
2. 「没做的现在一并全部都给做出来，不要等。」
3. （AI 复盘）「它们这些策略和现有库里的策略不要有交集，至少选股的逻辑上不要有交集。」

---

### ① 评分日变化：这是机制缺陷，不是文案问题

**根因**：`pos`（现价在箱体位置）和 `dwell_ratio`（谷底驻留）都吃最新收盘价，**逻辑上每天必变**。
但两个东西把它藏起来了：
- 缓存按 **mtime + 6 小时 TTL** 判断过期，不按交易日；
- payload 里**没有任何"变化量"字段**。

后果比慢更糟：昨天算完、今天新 K 线已入库、又没超过 ttl，页面就会**拿昨天的分数冒充今天的**，
用户完全看不出来。上一版我在文案里写"名单不变是它在继续磨"——那是**文案兜底**，进哥当场指出了。

**做法**（`viewer/universe_box.py`）：
1. 新表 `universe_box_hist(trade_date, code, score, pos, dwell_ratio, dwell_max_run, pct750,
   current, rank)`，每个交易日写**全量 passed2**（693 只，不是截断后的 40 只），保留最近
   `HIST_KEEP_DAYS=60` 个交易日。
2. 与上一交易日同 code 对比，算 `d_score`（分数变化）/ `d_rank`（排名变化）/ `is_new`。
3. **首日不编数**：没有上一日基准时 `is_new=None`（不是 `True`），前端显示「—」。
   这一条差点写错 —— 第一版把所有行标成"新进"，读起来像"这些票昨天都不在"，是误导。
4. `_variant_cached` 新增 `date_field` 支持：落盘 `trade_date` ≠ 最新交易日 → 立即重算，
   并给前端带 `stale_note`（"这一屏显示的还是旧数据"），**不静默返回、不假装最新**。
   `universe_box` 的 ttl 同时从 6h 放宽到 12h（真正的过期判断交给交易日比对）。

**前端**：表格新增「较上日」列（红=上移 / 绿=下移，与 A 股习惯一致）；
hero 显示「693 只在榜票里 X 只分数上移、Y 只下移、Z 只新进」，可核对。
另有 `history(code, days)` 接口可查单票分数轨迹（暂未接前端）。

**实测**（注入假昨日快照验证，测完已清理）：`d_score=+3.5`、`d_rank=692`（693→1）、
`is_new=False`，轨迹 `[('2026-10-30', 83.14, 693), ('2026-11-02', 86.64, 1)]` 全部正确。

### ② 准入闸门：基本面从"加分项"改"闸门"

**新模块 `viewer/gate.py`**。阈值不是拍的，是**先算杀伤面再定**（当日 693 只在榜票逐条试）：

    硬否决（剔除）                        软否决（扣分不剔除）
    pb≤0        1 只 (0%)               roe<-10      49 只 (7%)
    市值<15亿    5 只 (1%)               负债率>85    22 只 (3%)
    负债率>95    5 只 (1%)               营收净利双崩 26 只 (4%)
    roe<-30     12 只 (2%)              PE>150       54 只 (8%)
    ─────────────────────              ─────────────────────
    并集 18 只 (3%)，**榜单前 10 名零命中**   并集 130 只 (19%)

因此硬否决定得**窄**（只放客观、无争议、可核对的），软否决用来**排序**而不是删票：
每条 −2 分、封顶 −6。实测 693 → **675 只**，蒙草生态因「营收 −38% / 净利 −282% 双降」
从 86.6 降到 84.6、排名 1→3。

**两条口径判断（写下来免得以后有人改错）**：
- **不要用 PE 分位当主闸门**。实测全市场 PE_TTM 非正的有 **1723 只（31%）**，亏损占三成；
  而"箱体谷底"策略天生聚困境股（周期底部亏损是常态）。PE 分位一票否决会大面积误杀。
  真正稳定的估值锚是 **PB**（净资产不像利润那样能被一次性减值打到负），估值闸门只用 PB 分位，
  PE 只做极端值排除（>150 扣分）。
- **行业分位现在还不能用**：`plate_members` 只覆盖 3131/5590 = **56%**，做同行业 PB 分位会有
  一半票没有基准。故用全市场分位；等覆盖率 ≥85% 再切 `PB_PCT_SCOPE="industry"`（条件写在常量旁）。

**数据缺失不算违例**：无快照/无财报只记进 `missing`，绝不因为缺数据就把票剔掉。

### ③ AI 取数独立化：切断三路规则引擎产物

**实测到的"交集"具体在哪**（原 `build_context` 13 个分区中）：
- `selection` = 短线形态证伪 + 低波池 → **就是我们的选股结论**
- `oss` = 开源规则/因子重测结论 → **别人策略的结论**
- `harvest` = 局面判定 + 当日陷阱名单 → 局部是选股结论

这三路一喂，AI 不是"独立判断"，是**换个说法复述**。

**做法**：`AI_INDEPENDENT=1`（默认）时只喂**原始层**——market / mainlines / money / news /
attention / portfolio / evidence / last；并新增 `independence` 分区，把"为什么切、切了哪些"写进
prompt，让模型知道自己在独立模式下工作。`doctrine` 保留但**剥掉 `rules`**（docs 是用户自己的
知识库文档，rules 是机械化提炼的规则、属策略层）。
`picks_source` 字段随 ctx 落库（`ai_independent` / `rule_blended`），供 `review_score` 分开统计胜率。

**回滚**：`AI_INDEPENDENT=0` 恢复三路全喂。

**实测**（离线跑 `build_context` + `_render_user`，不调模型）：
ctx 分区确认无 `selection`/`oss`/`harvest`；`doctrine` 只剩 `docs`；渲染文本 8306 字，
独立性声明正常输出；关键词扫描「低波池 / 形态证伪 / 开源规则」**零命中**，
「陷阱名单」仅出现在我写的"系统没有把陷阱名单给你"这句说明里。
