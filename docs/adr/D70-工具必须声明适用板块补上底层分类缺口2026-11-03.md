## D70 · 工具必须声明「适用板块」——补上底层分类缺口（2026-11-03）

**来由**：进哥连续两次指出我在修「这一盘糊了的麻婆豆腐」而不是改菜谱。原话：
「我们集合了很多豆包视频上面的本土战法，又集结了金叉死叉这些方法，就工具包里边的很多技术技巧，
**那他们之前你就没想过说，谁适合短线、谁适合短线超跌、谁适合中线波段，你就没有分类吗？
然后你就没有让他们相互之间自己跑一遍吗？** 那这个才是问题关键。」
所以本条目不是修 FinRL 那件事，是修让那类事反复发生的结构缺陷。

**自查发现四个缺口（按严重度排）**

| # | 缺口 | 证据 |
|---|---|---|
| 1 | `tool_registry` **没有「适用板块」字段** | 只有 `kind`（view/filter/scorer = 形态）与 `source_kind`（github/bilibili/doubao/builtin = 来源）。问"谁适合短线"系统答不出——不是答不好，是没这个字段 |
| 2 | **内核判据被复制成了货架商品** | `pillar_hot` / `pillar_dip` / `pillar_policy` / `pillar_self` 四个工具的 `what` 开头就写着"四支柱之一"，即 `pillars.py` 的判据在 toolbox 里有第二份。改内核时货架上那份不跟着变，还显示"可用" |
| 3 | **同义重复** | `box_bottom`(箱体谷底) ↔ 中线波段箱体；`pick_oversold`(超跌反弹) ↔ `pillar_dip`(超跌修复) |
| 4 | **账本记错了东西** | `tool_run_log` 只记 `n_in/n_out/ms`（掉了多少只、多少毫秒）。要回答"谁更准"必须记**筛出票的 T+5 收益**；现在的账本只统计工作量，不统计效果 |

**本次只做缺口 1（其余三个待办，见文末）**

改动：
- `tool_registry` 新增两列 `pillars`（逗号分隔板块）与 `pillar_note`（★ 为什么归这几个板块，不可空）。
- `ensure_tables` 加 `_add_col_if_missing()`：老库走 `ALTER TABLE` 补列。
  **必需**——项目里已有 app.db，`CREATE TABLE IF NOT EXISTS` 对已存在的表是空操作，
  不加这步新列只会在新机器上存在，老机器 `SELECT pillars` 直接报错。
- 板块归属集中在一张 `PILLAR_MAP`（22 条），不散进 TOOLS 那 380 行自述里。理由：
  ① 一眼看全分布，方便判断"哪个板块工具太少"；② 配套硬拦；③ 纯新增，改动风险低。
- **`_pillar_of()` 硬拦**：缺标注 / 板块名非法 / 没写理由，一律 `RuntimeError`。
  给默认值等于允许"忘了标"，那就退回设计缺陷里了。加新工具却没写归属 → 服务启动就失败，
  逼着当场想清楚它服务哪个板块。这是「防遗忘」的硬门，与 NOT NULL 三列同一思路。

**分布结果（这是本次最重要的产出，不是工程细节）**

| 板块 | 工具数 | 其中**专属**该板块的 |
|---|---|---|
| 中线波段 | 14 | 缩量回踩、波浪位置（+箱体谷底主用）|
| 短线热点 | 11 | 短线冲浪、政策漏斗、方法共振 |
| 短线超跌 | 10 | 超跌反弹、超跌修复、MACD 底背离 |
| **长期埋伏** | **7** | **0 个** |

**长期埋伏一个专属工具都没有**——它用的 7 个全是与别的板块共用的（准入闸门、避雷 C 档、
箱体谷底、质量龙头、机构新进建仓、自学习选股、基金经理策略信号）。
这为"长线板块最弱"提供了结构性解释：**它没有自己的判据，只有别人的判据在它身上的复用。**

**刻意不做的事**
- 不给 pillars 字段设默认值（"通用"不能让系统自己填，必须人写明理由）。
- 不在本次就摘掉 `pillar_*` 四个镜像（缺口 2）。摘之前要先确认前端与漏斗没有引用它们，
  否则会当场断链——那是独立一次改动，混进来会让本次无法干净验收。

**待办（按顺序，未做）**
1. 摘掉 `pillar_*` 四个内核镜像，改为只读引用，消除双源（缺口 2）；
2. 合并 `box_bottom` / `pick_oversold` 的同义重复（缺口 3）；
3. `tool_run_log` 加 T+5 收益字段，复用 `metalearn.weights_from_ic` 的 IC 口径（缺口 4）；
4. **工具级 IC 归因**：每个板块内部按 IC 给工具排名，得出"谁在这个板块真有用、谁是负贡献"。
   做完第 4 步，"谁适合短线、谁适合中线"才是用钱投票的数据，不是我拍脑袋。

**推翻条件**
- 若某工具在两个板块的 IC 符号相反（如短线正贡献、中线负贡献），说明"多板块归属"是伪装的，
  应拆成两个参数化实例，而不是继续共享一条登记；
- 若第 4 步做完后多数工具的 IC 与 0 无法区分，说明瓶颈不在工具而在**板块层判据本身**，
  那时要改的是 `pillars.py` 而不是继续给货架添工具。

**验证**：`tools/smoke.py` PASS=23 FAIL=0；`pytest` 619 passed / 4 failed / 4 skipped
（4 个失败与改动前完全一致：2 个 D63 已记的 `board_flow_range_daily` 网络 mock、
2 个 `test_volume_units_e2e` 依赖实时行情，今日 f38 官方换手率 920819 返 0.13% 与 K 线路径 0.31% 不符）；
真库迁移后 22 个工具归属零缺失；前端 `node --check` 通过。
