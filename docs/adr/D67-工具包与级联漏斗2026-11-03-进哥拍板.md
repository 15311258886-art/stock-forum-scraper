## D67 · 工具包与级联漏斗（2026-11-03 进哥拍板）

**背景**：进哥第二次系统性地指出同一件事——「GitHub 上找到这么多方式方法技能，怎么沉淀成
相应的工具，不光你来使，我也能看得到、我也能使」；并给了明确的操作画面：
「符合 K 线预测的，5000 多只刷完只剩 2000 只，另一个策略再点剩 50 只，再筛剩 10 只」。
还要求每个工具带**功能介绍**（收录时间 / 为什么收 / 作用 / 优秀表现），
并且「淘汰的你也给我展示出来，标注出来就行了」+「要有淘汰原因」。

**问题诊断**：现有 8 个研究板块全是「读内容」（B站 3306 条 + 豆包 2701 条语料、基金经理
14661 行信号…），一条都落不到「选」。而闸门 / 箱体 / Kronos / 共振明明能算，却各在各的页面里，
互相不通。所以要做的不是再写策略，是**先装统一插口，再把方法论一条条编译成能插进去的工具**。

**做法**（`viewer/toolbox.py` + `viewer/static/toolbox.js`）：

1. **统一契约**：所有工具实现 `apply(con, codes, params) -> {kept, dropped, score, stats, note}`。
   `dropped` 必须带人能看懂的原因——不知道一只票死在第几级、为什么死，漏斗就是黑箱。
2. **三类工具**：`view` 观察器（只看不筛）/ `filter` 筛选器（收窄池子）/ `scorer` 评分器
   （打分排序，设了阈值才临时当 filter）。分类是「过时的也留着让人自己试」能成立的前提。
3. **新表 `tool_registry`**：`why` / `what` / `adopted_at` 三列 **NOT NULL**，
   写不进去就不许登记——进哥说「过些日子我就忘了为什么收它」，那就让机器不允许这种遗忘。
   `adopted_at` 取**模块首次入库日**（git 首次提交 / 文件创建时间），不是登记日。
4. **淘汰标注**：`status='retired'` + `retire_reason`（非空才允许）。退场的工具**不撤架**，
   列表里照样显示，打「已淘汰」徽章并写明原因，但不能进漏斗。`seed()` 只校准描述字段，
   **不覆盖 status / retire_reason**——否则每次重启都把人淘汰的工具悄悄复活。
5. **一级入口**：新 NAV 组「工具包」，放在决策台右侧（进哥原话「放到决策台旁边做成一个一级入口」）。
   不并进研究工具折叠区：那片是「看内容」，这里是「筛股票」，藏起来等于没有。
6. **离进程算**：整条链走 `_variant_cached`（`/api/toolbox/funnel`），带 `date_field=trade_date`
   按交易日失效。前端拿 `computing` 后自轮询。

**一期范围**（进哥认可）：16 个工具入库 = 14 个可用 + 2 个已淘汰示例，全部是现成能力的「装箱」，
不写新因子。14 个：`gate_admit` `box_bottom` `avoid_c` `reso_ab` `pick_ma_bull`
`pick_vol_break` `pick_oversold` `pick_quality` `holder_org` `kronos_kline` `pillar_hot`
`pillar_dip` `pillar_policy` `pillar_self`。二期才把 9 个语料方法论编译成因子。

**两个被数据推翻的第一版设计（记下来，别再犯）**：

- `holder_org` 初版是「机构合计持股比例 ≥ X%」→ 实测 400 只过 387 只（96%），**等于没筛**。
  改成「本期机构**新进 + 增持**的家数」：全库 5093 只有机构数据的票，≥1 家新进占 65%、
  ≥2 家占 33%，默认取 2 家才有区分度。信息量在**变化**，不在**持有**。
- 分数不能混在一列比大小：四支柱是 0~100，策略模板分 0.6~288 都有
  （`quality_leaders` 全在 1 分附近、`oversold_rebound` 能到 288）。
  所以漏斗返回 `score_src`，表头写「得分 · 来自『XX』」——把尺子亮出来，而不是藏背后。

**实测**：
- 全市场 `5264 → 闸门 5012 → 箱体谷底 594（驻留≥30%/箱体≥1年）→ 机构建仓 276`。
- 预置链「超跌反转」：`5264 → 5012 → 317 → 10`，正是进哥说的「刷到剩 10 只」。
- 取数路径分流：把 5012 个代码显式传给 `ohlcv_bulk` 要 **42 秒**，不带 codes 走全宇宙批量只要
  4 秒。所以 `_apply_box` 在池子 ≥2000 时先取全量再内存求交集（5012 只 42s → 7s）；
  小池子（几十只）反过来按 code 取（300 只 0.9 秒）。
- 离进程里单次箱体实测 40 秒（独立跑 8 秒）——**如实写进提示**，不承诺 8 秒。

**推翻条件**：
- 若工具越加越多、漏斗结果却越来越差，说明"多工具求交集"在不相关的维度上做，应改为
  分组内求交集（同一族工具互斥，跨族才叠）。
- 若 `retired` 工具长期无人点开，说明"留着让人自己试"是伪需求，应改为归档页。
- **不许**为了"漏斗看起来收窄得漂亮"去调工具的淘汰阈值；每个阈值必须能从数据里算出来
  （如 65% / 33% 那组分布）。

/ 1 skipped；`tools/smoke.py` PASS=23 FAIL=0；`py_compile` + `node --check` 全通过；
`tools/shot_toolbox_verify.cjs` 四页零 pageerror、`docW==winW==1600`、
能力卡字段齐（为什么收它/作用/实测表现/短板/最近一次运行）、
淘汰卡有原因框、漏斗节点 5264→127→5、淘汰行能显示「第 2 级淘汰：…」。
