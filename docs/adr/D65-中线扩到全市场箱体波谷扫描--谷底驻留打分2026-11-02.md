## D65 · 中线扩到全市场：箱体波谷扫描 + 谷底驻留打分（2026-11-02）

**进哥原话**：「中线就是你找 5000 多只股票里边，属于那种总是在一段时间之内、它有周期性这种
波峰和波谷的。只要这一段时间处在波谷期间之内，那就应该一直显示，然后只不过就是评分越接近
波谷、它在波谷震荡的时间越长，你应该更加关注、打分会更高一些。」

**根因**：中线主表（`/api/screener_lowbox`）的扫描池是「关注池 ∪ 涨幅 Top30」再截断到 **64 只**，
而箱体/分位/CV 这些**全是分位数类指标** —— 在 64 个样本上算出来的"分位"没有统计意义，
排出来的名次是假的。不是筛得严，是池子根本不够。库里 5575 只 / 1709 万根日 K 一直躺着，
全市场纯计算只要 1 秒级，**扩池从来不是性能问题**。

**做法**：新建 `viewer/universe_box.py`（不改 lowbox 一行）。
1. **两级扫描**：一级纯本地 K 线跑全市场（`evaluation_universe()` 5003 只，只算箱体位置/分位/CV/斜率），
   二级只对粗筛结果算驻留/触及。绕开"逐只外部接口"的成本。
2. **驻留越久分越高**（进哥要求的核心）：`dwell_ratio` = 近 250 日落在箱体下 1/3 的天数占比，
   `dwell_max_run` = 最长连续停留。打分 **驻留 35% + 位置 30% + 规整 20% + 触及 15%**，
   驻留是四维里权重最高的 —— 直接对应"震荡时间越长打分越高"。
3. **波谷期间一直显示**：只要现价落在箱体下 1/3 且驻留 ≥15%，就一直留在榜上，
   当天涨 1% 不会被踢出去（这是"一直显示"的字面落地）。
4. **准入**：从 `universe_filter.evaluation_universe()` 出发，不碰剔除池里的 ST/停牌/僵尸票。
5. **离进程算**：实测 7~8 秒（取数 5.9s + 扫描 1.0s），走 `_variant_cached` 落盘（ttl 6h），
   首次回 `computing=true`，前端 `_deskPoll` 自动接上。新增路由 `/api/universe_box`（已入快照）。

**实测结果**（2026-11-02 生产数据）：
`universe=5003 → passed1=1408 → passed2=693`（在谷底磨着）→ 取前 40。
榜首蒙草生态(300355)：750 日箱体 3.0 年、现价在箱体从底往上 **5%**、近 250 日 **100%** 的交易日
待在谷底区、最长连续 **250 日**、触及 71 次。子进程实测 **10.0 秒**算完落盘。

**与 lowbox 的分工（并列，不替代）**：
`lowbox` = 小池子、深加工（基本面 + 估值 + 国资加分，要逐只外部接口）；
`universe_box` = 全市场、只筛形态（找"哪只票正在谷底磨"）。
决策台中线页现在主表是 `universe_box`，lowbox 降级为下面的「同池深加工」次表。

**已知边界**（写进模块 docstring，不许忘）：
- 成交额用 `close × v` 近似（本地 K 线只有成交量），只用于"剔除僵尸股"这一流动性门槛，
  **不要拿它做精确金额统计**。
- 箱体固定 750 日（约 3 年）窗口随日期滚动 —— 是"当前箱体"，不是历史固定锚。
- 上市不足 750 日的票不入池（算不出 3 年箱体），在 `skipped` 里如实计数（3595）。

**同轮一并修掉的两个自查项**：
1. **企稳档可见化**（`renderDeskDip`）：后端早就算了 `level` 0/1/2/3，但前端只塞在 reason 长文本里，
   档 1（仅止跌、假信号率 55~65%）和档 3（连续不创新低 + 站上 5 日线）在页面上一模一样长。
   现在单独成一列：档2/3 蓝「已确认」、档1 橙「仅止跌」、档0 灰「无迹象」，并在 hero 里点明
   "档1 当观察，别当买点"。
2. **验收脚本选择器 bug**：`shot_desk_verify.cjs` 里 `document.querySelector(".dk-hero")` 拿的是
   四个面板同时存在时的**第一个**（热点页的），导致每页都在验热点。改成取"当前可见"那个。
3. **两套避雷口径对齐**（本来是自查项①，挖下去发现根因不是我以为的那样）：
   页面上「⚠避雷」红标**不是** `viewer/avoid.py` 算的，它走 `/api/avoid` →
   `resonance.avoid_payload()`，口径是「共振卡 tier C 低分 + 负面归因条数」——2026-11-02
   实测 **507 只 C 级（占全市场 13%）**；而 `avoid.compute()` 算的是另一件事（放量/龙虎榜/MACD
   的下跌风险实时评分，high≥7 / mid≥2）。**一开始我接错了模块**，接上才发现：
   当日超跌 5 只**全部 5 只**都是 tier C —— 不是巧合，是 tier C 与"长期阴跌"天然高度重叠
   （跌了两三个月的票评分必然低）。若按 tier C 直接剔除，超跌名单会**全军覆没**。
   最终分工：`avoid.compute` **high 档 → 剔除**（硬风险，不该出现在"抄底"名单）；
   `resonance` **tier C → 打标不剔除**（软信号，与"阴跌够久"是两个时间尺度：C 档说未来 5 天
   相对强弱，超跌修复赌 1~2 周反弹）。两个模块任一不可用都不阻断名单，只留痕。
   前端在 hero 里把这段矛盾**正面讲透**（命中 ≥60% 时才显示），不靠沉默糊过去。
   实测 `note`：「风控对齐：下跌风险高风险剔除 0 只、中风险打标 0 只；共振卡 C 档交叉打标 5 只。」
4. **企稳档标签被拆行**：`app.css` 为防横向溢出统一去掉了 `.dk-tag` 的 `nowrap`，
   结果"档3 确认"在 12% 宽的列里被拆成两行（截图确认）。只对这一列内联恢复 `nowrap`
   （文案固定 4~6 字符，撑不破页面），并把列宽调到 13%、文案压到「档3 确认/档1 止跌/档0 无」。

**已知未修的风险（如实记录，不粉饰）**：
- 中线与超跌的重叠未在代码里拦（只靠分位/阴跌两套判据自然分开）。
- 阴跌票与箱体谷底票变化都慢，名单可能连续一两周不换 —— 页面已写"那是它在谷底继续磨，
  不是系统卡了"来预防"以为工具坏了"的误判，但这是文案兜底，不是机制保证。
- 超跌支柱的"确认档"数量在两次重算间从 249 只变成 85 只（名单 5 只未变），
  说明 249/85 这个中间计数对输入数据的微小变动敏感，**不要拿它当稳定性指标**。

**推翻条件**：若"谷底驻留 ≥15%"的票在后验里 T+20 胜率不显著高于"刚到箱底"的票，
则"磨得越久越值得关注"在 A 股不成立，`W_DWELL` 应降权甚至反向。
**不许**为了让名单"看起来像在动"而调低 `min_dwell` 或缩短 `BOX_WIN`。
