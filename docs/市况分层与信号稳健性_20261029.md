# 市况分层与信号稳健性（2026-10-29）

## 0. 一句话结论

把 250 日、5300 只的全样本按市况拆开，并对每个交叉格做前后半段检验，结果是：

> **27 个（信号 × 市况）组合全部完成检验：0 个「稳健有效」、11 个「稳健有害」、16 个「前后不一致」。**

即：这套信号体系在样本内**没有可复用的正 alpha**，但有一批**可确认的负 alpha**；
真正通过检验的规律不是"换一套信号权重"，而是"弱势市里持有本身就亏钱"这条风控事实。

---

## 1. 为什么要拆

上一轮「信号战绩」的全样本口径给出：T+5 胜率 46.0%、扣费后 45.2%，几乎无信号跑赢基线。
这个结论**本身不可信**，因为：

    把上行、震荡、下行三种市况的样本混在一起求平均，
    等于把「择时」和「选股」搅成一团 —— 熊市里全市场都在跌，再好的选股信号平均收益也是负的。

真正该问的是：**同一市况内，这个信号选出来的股票，比当天全市场平均水平更好还是更差？**

拆开之后确实看到了结构：逆势类（KDJ超卖金叉、RSI6超卖、跌破BOLL下轨）在弱势市正超额，
追涨类（MACD零上金叉、Supertrend上方）在弱势市 -7pt 量级负超额，两者在全样本里互相抵消。
**但继续做稳健性检验后，这些结构几乎全部没有通过**——见第 4 节。这一步救了一次严重的过拟合。

---

## 2. 市况怎么定义（两次自我修正）

口径：**全市场等权指数的 20 日累计收益**，即每日全市场个股收益的**均值**滚动 20 日复利累乘；再以
截至当日、过去 250 个交易日的 **33/67 分位**切三档。

### 坑 1：中位数累乘会系统性低估

第一版用「个股收益中位数」累乘。中位数按定义必然低于均值（收益分布右偏），累乘后负偏逐日放大：
实测均值 -4.60%、中位 -3.76%，268 天里 **153 天下行、上行只有 18 天** —— 上行档样本不够下任何结论。
等权指数的日收益就是**均值**，这才是"全市场涨了多少"的正解。修正后均值 +0.51%，分布 down 111 / range 75 / up 82。

### 坑 2：绝对阈值在弱市样本里失效

第一版用 ±3%。但本样本期 20 日等权收益的 90 分位才 +2.11%，±3% 实际等同于"只有极少数天才算上行"。
改用**滚动分位**切档后三档自动均衡，且完全没有前视（只用截至当日的历史）。

### 三档的正确读法

| 标签 | 含义 |
|---|---|
| 强势 | 20 日等权收益 > 过去一年 67 分位 |
| 震荡 | 33~67 分位之间 |
| 弱势 | < 过去一年 33 分位 |

它是**相对过去一年**的强弱，不是绝对涨跌（弱势市也可能只是"跌得比别人慢"）。绝对方向另由 `ret20` 的符号表达。

当前（2026-10-29）：**弱势，20 日等权 -12.93%，当日上涨家数占比 32%**。

## 3. 拆开之后看到什么

### 3.1 分状态基线（税后均值）

| 前向 | 强势 | 震荡 | 弱势 |
|---|---|---|---|
| T+5 | -0.02% | -0.08% | -0.39% |
| T+10 | -0.11% | +0.02% | -0.50% |
| T+20 | -1.32% | -0.27% | +0.71% |

全样本 T+10 基线是 -0.24%，而这个数字**在任何单一市况下都不成立**——混算掩盖了 0.5pt 量级的结构差。

### 3.2 信号方向随市况反转（超额胜率 pt）

| 信号 | 强势 | 震荡 | 弱势 |
|---|---|---|---|
| KDJ超卖金叉 | -7.8 | -2.2 | **+2.1** |
| RSI6超卖 | -7.7 | -5.2 | +1.1 |
| 跌破BOLL下轨 | -4.4 | +0.2 | +1.4 |
| MACD零上金叉区 | +0.7 | -2.2 | **-7.7** |
| 股价在Supertrend上 | -0.4 | -2.0 | -6.8 |
| 放量 | -4.6 | -5.3 | -6.9 |

看起来非常干净：逆势类与追涨类的符号完全相反。**如果就此按市况切换权重，会错得非常彻底**——见下节。

## 4. 稳健性检验（本轮最关键的一步）

### 4.1 有效独立窗口：49 万样本是假的

T+20 的前向收益，相邻两个交易日窗口重叠 19/20。一行 49 万的样本表，真正**不重叠**的观测只有
`交易日数 / fwd` 个：

| 前向 | 交易日 | 有效独立窗口 | 结论等级 |
|---|---|---|---|
| T+5 | 283 | 56.6 | 仅供方向参考 |
| T+10 | 278 | 27.8 | 仅供方向参考 |
| T+20 | 268 | **13.4** | **不足以下结论** |

拿 n=491486 去算显著性，等于把同一段行情数了 20 遍。所有结论都已按此降级表述。

### 4.2 前后半段：结构立刻塌掉

把样本按交易日切成前后两半，分别算每格超额：

| 信号 | 强势 h1/h2 | 震荡 h1/h2 | 弱势 h1/h2 |
|---|---|---|---|
| 跌破BOLL下轨 | +2.4 / -7.0 | +6.4 / -6.6 | **+15.1 / -7.7** |
| RSI6超卖 | +1.7 / -10.9 | +0.0 / -9.6 | **+16.3 / -6.1** |
| CCI超卖 | -1.9 / -2.2 | +1.5 / -1.3 | **+12.5 / -5.7** |
| KDJ超卖金叉 | -6.1 / -10.7 | -2.9 / -5.1 | +9.5 / +0.1 |
| 放量 | -5.5 / -4.1 | -6.4 / -4.7 | -6.3 / -6.9 |

所有"弱势市抄底有效"的格子，都是 **h1 大正、h2 大负**：只在前半段那波行情里成立，后半段完全反转。
同理，T+20 的"弱势市 +0.71% 反弹"也在前后两半翻转（+0.84% / -0.47%），只有 13.4 个有效窗口，不可用。

### 4.3 最终三态判定（27 格全覆盖）

判据：某格 h1 与 h2 **都** ≥ +1pt = 稳健有效；**都** ≤ -1pt = 稳健有害；异号或幅度不足 = 前后不一致。

| 判定 | 数量 | 具体 |
|---|---|---|
| 稳健有效 | **0** | —— |
| 稳健有害 | **11** | 放量（三档全部）、MACD零上金叉（震荡/弱势）、Supertrend（震荡/弱势）、KDJ超卖金叉（强势/震荡）、CCI超卖（强势）、PDI（震荡） |
| 前后不一致 | **16** | 逆势类在市场弱势档、追涨类在强势档等 |

**"稳健有害"是可直接落地的负面结论**：这些组合历史上两段都跑输同市况平均，不该作为买入依据。
它也为上一轮已做的技术类降权（`tech_factor` 0.868 → 0.693）提供了分段证据。

## 5. 落地

| 层 | 内容 |
|---|---|
| 数据 | `market_regime`（逐日市况：regime/ret20/breadth/分位界）、`signal_regime`（信号×市况×前向的税后指标与超额）、`signal_baseline_regime`（同市况基线）、`signal_regime.stab`（三态稳定性标记） |
| 计算 | `viewer/regime.py`（全历史重算 1.9s）、`viewer/signal_backtest.py --diagnose`（68s → 约 90s，多算前后半段） |
| 诊断 | `tools/regime_robust.py`（分状态基线的前后半段对比 + 有效窗口数） |
| 接口 | `GET /api/signal/regime?fwd=10`（0.08s），返回当前市况、同市况基线、27 格明细、有效窗口数与结论等级 |
| 前端 | 「信号战绩 · 分市况」区块：当前市况置顶，按当前市况超额排序，每行带稳定性标签（稳健有效/稳健有害/前后不一致/未检验） |
| 调度 | `regime_daily` 日更任务，排在 `indicators_daily` 之后（跑早了会拿昨天收盘算今天的市况） |

### 接口与页面刻意分开的原因

`/api/signal/evidence` 回答"整体有没有用"，`/api/signal/regime` 回答"当前市况下有没有用"。
两者可以给出**相反**结论。混在一个返回体里，最容易被误读成"整体=当前"。

## 6. 局限（以及不要用它做什么）

1. **样本期只有 288 个交易日**，且内部是"急跌—反弹"结构。任何"某市况下有效"的说法都可能只是这一段行情的特征。
2. **T+20 不可用**：13.4 个有效独立窗口，不构成统计证据。
3. **信号之间高度重叠**：同一天同一只股常同时触发多个信号，不同信号的样本并不独立，不能把它们当相互验证。
4. **不要按市况切换权重**：16 个格子前后不一致，说明这个方向是过拟合。
5. **可以做的**：把"稳健有害"的组合在弱势市直接屏蔽；把市况用于**仓位与追涨约束**（弱势市 T+5/T+10 平均收益前后两段一致为负），而不是用于选股。

```bash

```

## 8. 变更与验证

- 回测引擎由「存全量收益 list」改为「累积统计量 `[n, sum, sumsq, wins, wins_net]`」：
  一次遍历同时得到总表与分状态表，内存恒定，且不存在两份数字对不上的可能。
- 等价性验证：40 万条合成样本上，统计量累积与 numpy 直算逐项差 ≤ 1.7e-15（胜率差 0）。
- 与 2026-10-29 早间的 `signal_backtest_bak_20261029` 相比，胜率差 1.3~1.6pt、样本量 +2~3%：
  来自当日数据链补全（指标层覆盖变多），**不是实现差异**。两套数字不可直接对比。
- 发现的实现缺陷（已修）：诊断块曾运行在 `con.close()` 之后，`ALTER`/`UPDATE` 全部静默失败，
  表面上打印了结论、表里一列都没写。现改为连接在 `return` 前统一关闭，且失败不再静默。
