# 产品内核演进规程

> 立规时间：2026-11-03
> 立规起因：进哥指出我把「拆解外部方法」直接落成「往工具箱加一个工具」，而忽略了第一顺位——
> **外部方法首先是用来升级决策台四 tab 背后那套判据的**。
> 他的原话：「工具包是工具包，然后我们现在调用底层逻辑算法，这是我们自己的东西……
> 那这个计算逻辑是你应该不断迭代和提升的过程，对吗？」
> 「你不能说我们弄了很多的技能，然后我们自己不去用，那我们学这些技能、找这些技能意义何在？」

---

## 0. 两个层面，永远不要混

| | 产品内核 | 工具货架 |
|---|---|---|
| 是什么 | 决策台四个 tab 背后的**判据与打分逻辑** | `viewer/toolbox.py` 里可插拔的 view / filter / scorer |
| 在哪 | `viewer/pillars.py`（四支柱）、`viewer/universe_box.py`（箱体）、`metalearn`（IC 自加权） | `viewer/toolbox.py` + `viewer/factors.py` |
| 衡量标准 | **这套判据对不对、比昨天更准了吗** | 这个工具好不好用、能不能单独调用 |
| 谁受益 | 用户每天打开看板看到的东西 | 用户做级联筛选时的手动工具 |
| 更新频率 | 应该持续演进（这是产品的成长） | 有值得的就加，没有就不加 |

**规矩：学到任何外部方法，第一顺位问「能不能替换/改进四 tab 的现有判据」，第二顺位才问「这东西单独拿出来有用吗」。**

默认路径**不是**"做成工具加进货架"。默认路径是"先在映射表里找它对应哪个 tab"。

---

## 1. 决策台四 tab 的现状（2026-11-03 核对代码）

| Tab | 后端位置 | 现在的判据核心 | 已知短板 |
|---|---|---|---|
| 短线热点 | `pillars.py :: pillar_policy_funnel` | 政策/板块资金漏斗：板块净买入、板块内上涨占比、龙头识别 | 缺「趋势强度」量化，靠资金额单维 |
| 短线超跌 | `pillars.py :: pillar_dip_revert` | 阴跌持续性 + 企稳确认（分档放行） | 「超跌有多深」缺统一标尺，各票不可比 |
| 中线波段 | `universe_box.py` | **静态箱体**：730 日高低点为箱体，现价在箱体下 1/3 = 谷底区，按谷底驻留天数加分；叠加估值/基本面加减分 | 静态箱体会被一次极端行情**永久拉宽**，之后所有票都"在谷底"，失去区分度 |
| 长期埋伏 | 估值/周期分位一侧 | 多年度估值分位 + 周期长度 | 与日频指标无关 |

另有一层 **`pillar_self_learn` 引擎自加权**：用 T+5 的 IC 给各支柱学权重（`metalearn.weights_from_ic`，
等权先验做收缩锚）。**这是外来方法最该灌进去的地方**——不用改判据本身，
先让它对"新判据的信噪比"给出权重判断。

## 2. 每次拆完外部方法，必须填这张映射表

不填完不许说"下一步做 A 还是 B"。

| 字段 | 说明 |
|---|---|
| **外部方法** | 名字 + 仓库地址 + 已拆到的层级（L0/L1/L2/L3） |
| **对应 tab** | 四个 tab 里哪个最像；**如果四个都不像，明确写"无对应"** |
| **现有判据** | 那个 tab 现在具体怎么算的（函数名 + 关键参数） |
| **它能改什么** | 替换 / 补充 / 加权 / 无关，四选一，写清改哪一行逻辑 |
| **预期提升** | 预计改善哪个指标（命中率、区分度、名单稳定性、换手率） |
| **怎么验证** | 用 `pillar_self_learn` 的 IC 口径，还是影子期对比，具体到能跑的命令 |
| **风险** | 换上去可能更差的地方 |

**只有填完这张表，才有可能出现"提内核"和"加工具"两个动作；不许跳过表格直接给选项。**

## 3. 第一个样例：FinRL 的 8 个指标该往哪儿放

FinRL 的 8 个指标（`macd / boll_ub / boll_lb / rsi_30 / cci_30 / dx_30 / close_30_sma / close_60_sma`）
本质是**短周期偏离与波动的度量**，全部 IC 为负（反转方向）。按表走：

| 对应 tab | 判定 | 理由 |
|---|---|---|
| **中线波段** | **有真实可替换点（优先做）** | 它现在用**静态箱体**（730 日高低点）。而 `boll_ub/boll_lb` 是**动态箱体**（20 日均线 ± 2σ）——波动率收缩时箱体自动收窄、扩张时自动放宽。静态箱体一旦被一次极端行情拉宽就永久失真，这正是当前"名单连续很多天不变"的结构性原因之一（不全是判据设计意图）|
| **短线超跌** | **有补充价值** | 「超跌有多深」现在缺统一标尺。`布林%B`（0=下轨、1=上轨）能把全市场放到同一把尺子上，个股之间可比。这是判据补强，不是替换 |
| **短线热点** | 弱相关 | 只有 `dx_30`（趋势强度）勉强能用，用于区分"有方向的板块"和"乱涨"。资金流维度它完全没有 |
| **长期埋伏** | **无对应** | 日频短期指标，与多年度估值分位、周期长度不是一个尺度 |
| **引擎自加权** | **可直接喂** | 把这些维度接进 `self_learn` 的 IC 计算，让它自己决定给多少权重，不用我拍 |

**这张表给出的结论和上一版的 A/B 完全不同**：不是"做成工具"也不是"重跑 RL"，
而是**先把中线波段的静态箱体换成动态箱体做 A/B 验证**——因为那是唯一一处能直接改善用户每天看到的东西。

### 3.1 第一个样例的落地结果（2026-11-03，D71）

映射表跑完了，结论已经落地过一次。**结果和预期不一样，这一节记的是真实结果，不是计划。**

做了：`viewer/universe_box.py` 加了一把**动态**尺子（布林 20 日 ±2σ 的 `%B` 分位，
`boll_pctb_rank`），与静态箱体**并行**存在，三档开关 `UNIVERSE_BOX_MODE` = `static`（默认）/
`blend` / `dyn`。默认 `static`，线上**数值、排名、分项**与改前一致（payload 是加法式扩展：
每行多 8 个键，前端不读新键故不影响渲染）。

验证（`tools/ab_box_mode.py`，8 个样本日 × 14 个月，T+5/10/20 严格无前视）：

| | static（默认） | blend | dyn | 候选池（参考） |
|---|---|---|---|---|
| Top40 T+5 均值 | +0.62% | +0.66% | +0.62% | +0.39% |
| Top40 T+10 均值 | +0.53% | +0.57% | +0.55% | +0.18% |
| Top40 T+20 均值 | +0.18% | +0.13% | +0.47% | +0.38% |
| 配对胜出天数（T+20） | — | 4/8 | 3/8 | — |
| Top40 名单 Jaccard | — | 0.633~0.778 | — | — |

（上表是 2026-11-03 QA 指出闸门前视后**重跑**的数字。第一版数字里 `static T+20 = +0.29%`、
`候选池 +0.40%` 等已被证伪作废 —— 差别见 `DECISIONS.md` 的「D71-修订」。
重跑后闸门只有 2/8 天真正生效（`stock_daily_snapshot` 只有 4 个交易日、`fundamentals` 是每股一行的
单快照），所以这批绝对数字是**混合口径**，不能当成线上含闸门的成绩。）

**结论：动态尺确实换掉了名单（40 只里换 7~10 只），但没有让名单更赚钱。所以默认没改。**
并且 `dyn` 那个好看的 T+20（+0.47%）是**只赢 3/8 天、靠两天拉起**的肥尾，不算优势 ——
这条恰恰是"只看均值会被骗、必须看配对胜率"的现成例子。

这条结果对"规程"本身有三点价值，比"提升"更重要：

1. **"有 IC" ≠ "接进去就更好"。** 单维 IC（`布林%B` 训练 −0.0535 / 测试 −0.0546，同号）
   证明这个量有信息，但把它混进一个已有四维打分的总分里，信息会被另外三维稀释、
   也被权重结构吃掉。**IC 是准入条件，不是收益承诺。** 这两件事以前混着说，现在必须分开。
2. **换标尺和换判据是两种动作。** 这次只动位置分一项（其余三维与权重一字未改），
   所以 A/B 能干净归因；也正因为只动了一项，天花板注定不高。下次要提内核，
   该问的是"四维权重结构对不对"，而不是继续换尺。
3. **"默认不变"必须是可断言的事实，不是承诺。** 落地时配了 17 条口径断言
   （`tests/test_universe_box_mode.py`），其中三条专门钉"static 与老公式逐位相等""`parts`
   键集不许变""切模式后不许跨尺算日变化"。靠肉眼看榜单看不出 0.5 分的漂移。
4. **"回测干净"必须被验证，不能自证。** 第一版数字里有一层**闸门前视**：`gate.py` 取财报
   没有报告期约束，而 `fundamentals` 是单快照 —— 8 个历史样本日用的全是 2026 年之后的财报
   （旧代码对三个相差 14 个月的样本日给出**完全相同**的 hard 105 / soft 415，这就是铁证）。
   QA 用"不同样本日应给出不同结果"这种最朴素的方式抓出来的。
   **教训：无前视不是"我写的时候想着无前视"，是"有一个检查能证明它无前视"。**
   修完之后又冒出一条：`report_date` 是报告期不是公告日，仍有 ≤2 个月公告滞后前视，
   库里没有公告日字段就消不掉 —— 只能标注，不能装看不见。

顺带暴露一个**换尺修不了的**问题：两个模式的 Top40 在 T+20 上都没跑赢自己的候选池
（static **−0.21pp** / blend **−0.25pp**，修正后数字）。也就是"位置 + 驻留"这套判据在
20 日尺度上贡献接近 0，而在 T+5/T+10 上是正的（+0.23 / +0.35pp）——
**排序的价值集中在短周期**。这才是下一件该做的事（已在 D71 里记为待立项，
不许被"换尺 A/B 做完了"盖掉）。

## 4. 三条红线

1. **不许上来给选择题。** 说"下一步 A 还是 B"之前，必须先走完第 2 节的映射表。让用户拍板的前提是：
   我已经把选项收敛到唯一合理的那条，并且说清为什么其他三条不成立。
2. **不许为了攒工具而攒工具。** 货架上的工具如果内核用不上、用户也不会单独点，那就是负债。
3. **内核改动必须留痕。** 每次改判据都要在 `DECISIONS.md` 记：改前是什么、改后是什么、
   为什么改、怎么验证的、什么条件推翻。**内核变更的留痕要求高于工具变更。**

## 5. 一句话记住

> **找技能不是为了攒技能，是为了换掉自己身上不够好的那部分。**
> 学到的东西如果只进了货架、没进内核，那这次学习就是浪费。
