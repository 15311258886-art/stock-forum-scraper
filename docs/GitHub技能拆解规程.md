> 立规时间：2026-11-03

> 适用范围：**所有**从 GitHub / 外部分享里拆技能、策略、因子、工作流的场合，不限本项目。

## 0. 总纲：拆的是「配方」，不是「原料」

进哥的原话（麻婆豆腐）：

> 「每个人都可能分享出自己的步骤，这个步骤可能就是一款 skill。同样是一款麻婆豆腐，
> 市面上主流做法有 100 种，但大家比较认可的只有三种——这三种才是有价值的。
> **大家用的因子都一样，只不过是对因子的分量比例调试有区别，最后做出来的东西就不一样**，
> 它最后筛选出来的股票也不一样。」

推论，写死：

- **列出"它用了 RSI、MACD、布林带"等于没拆。** 原料谁都知道，值钱的是配比、顺序、火候。
- 被市场筛出来的少数版本，价值在**参数与工序**，不在组件清单。
- 而"它套美股、我们套 A 股"只是**食材产地**不同，**做法没有区别**。所以做法必须整套搬过来，
  只在数据口径、可执行性、成本这些"产地"环节做必要替换。

## 1. 四层拆解标准（L0→L3），必须四层全答完

| 层 | 名称 | 要抽出什么 | 判"拆到了"的标准 |
|---|---|---|---|
| **L0** | 原料 | 用了哪些因子 / 字段 / 数据源 | 能列出源码里**写死的常量或列名**，附`文件路径:行号` |
| **L1** | 配比 | 每个因子的权重、归一化方式、合成公式 | 能写出合成表达式（加权和？排序打分？交叉条件？门槛？） |
| **L2** | 工序 | 判断的先后顺序、前置过滤、状态依赖 | 能画出决策流程：先过什么 → 再判什么 → 什么情况直接否决 |
| **L3** | 火候 | 阈值、超参、触发条件、调仓频率 | 每个阈值都能给出**原文取值**与可容忍区间 |

> **只完成 L0 = 没拆。** 这是硬线，不接受"大致了解了"。

### 常见只拆到 L0 的迹象（自查）
- 说得出"它用了动量+波动率"，说不出"怎么加权、谁先谁后"
- 说得出"它要 RS I>70 才卖"，说不出"这个 70 是不是调过、灵敏不灵敏"
- 拿"指标清单"当结论交付

## 2. 三条「不许」（2026-11-03 那次三条全踩）

| # | 不许 | 那次怎么踩的 |
|---|---|---|
| 1 | **不许靠印象。** 没读到源码前，不许说"它用的是 XX"、"它不支持 XX" | 凭印象说 FinRL 是"美股口径、A 股拆不过来"。实际它自带 `tusharedownloader.py`（Tushare 中国数据源），`config.py` 里有 `TIME_ZONE_SHANGHAI # Hang Seng HSI, SSE, CSI` |
| 2 | **不许拿自造替代品冒充原文。** 复刻品与原文的每处差异必须逐条列出 | 我手搓 12 维（动量/波动/量比）≠ 它 `config.py :: INDICATORS` 的 8 个 stockstats 指标，一条都不重合；任务也从"N 只票组合分配"被我换成"单票三档择时"。却拿它当"FinRL 不行"的证据 |
| 3 | **不许把"跑不动"当"不行"。** 缺依赖、接口不通是工程障碍，单独记，不进结论 | 把 `torch.optim` 崩溃、没装 gym/SB3 揉进了"算法层不拆"的结论里 |

## 3. 「流行」必须先当证据，不是噪音

一个仓库有大量使用者 / 引用 / 论文，**先假设它有效**，任务是去找**它为什么有效**。

只有**同时**满足下面三条，才允许写"不适用"：

1. 用**它真实的特征清单、动作空间、奖励函数**复现过（不是简化版、不是"类似"）；
2. **扫过关键超参**（不是默认值跑一把就定）；
3. 能**解释失效原因**，且原因属于下面三类之一：
   - 数据口径（复权方式、停牌处理、财报基准日）
   - 市场结构（T+1、涨跌停、散户占比、做空限制）
   - 频率（日频 vs 分钟频 vs 组合再平衡周期）

**三条缺一条，只能写「未验证」，不能写「不行」。**

## 4. 移植的正确姿势：只换食材，不换做法

### 允许改（因为这是"产地"差异）
- 数据源、复权方式、交易日历
- 停牌 / 一字板 / 涨跌停的**可执行性**处理
- 交易成本（A 股卖出单边印花税、最低佣金）
- 股票池（美股指数成分 → A 股全市场 / 中证800 / 成交额前 N）

### 不允许擅自改（改了必须标「偏离」并单列理由）
- 特征定义（公式、窗口长度）
- 因子合成方式与权重
- **阈值方向**

> **阈值方向最危险。** 实例：FinRL 的 `turbulence`（252 日滚动协方差 + 马氏距离）在美股是
> "超阈值就清仓躲风险"。在我们的 A 股样本上（30 / 50 只两档，可用 596 天），
> 95 分位以上的 30 天之后次日平均 **+0.913%**，其余 566 天 **−0.007%** —— **高波动后是反弹**。
> 机制可以搬，**方向照抄会做反**。必须用本地数据重新验证方向，并明确标注"与原版相反"。

## 6. 开工自检七问（每次动手前逐条回答，答不上就别下结论）

1. 我读的是**它的源码**，还是我的印象？
2. 我复现的特征清单，和它 `config` / 常量文件里写死的那个，**逐条对上**了吗？
3. 我测的**任务类型**和它一致吗？（单票择时 / N 票组合分配 / 截面分类 / 排序）
4. 它的**动作空间**是连续还是离散？维度是什么？我的呢？
5. 它的**奖励函数**原文是什么？我的呢？
6. 我说的那些"用不了"的理由，哪几条是环境问题、哪几条真是方法问题？
7. 我说"不行"之前，**扫过几个超参**？

## 7. 标准作业流程（SOP）

1. **拿源码**：优先 GitHub 连接器（`mcp__github__get_file_contents`）。
   `git clone` 被墙 **不代表** 拿不到——那次 `git ls-remote` 报 `curl 52`，
   但连接器直接读到了 `finrl/config.py`。**别因为直连失败就放弃。**
2. **定位三件核心文件**：
   - 常量/配置（特征清单、指标列表、超参默认值）
   - 核心算法或环境（状态·动作·奖励·执行时点）
   - 数据预处理（复权、缺失、股票池、幸存者偏差）
3. **抄三样原文**（逐字抄，不转述）：特征清单、`step()` 里的奖励计算、动作→交易的映射。
4. **补 L0-L3 四层表**（第 1 节）。
5. **依赖判定**：能装就装它**原生的库**（例：`pip install stockstats`，用它自己的公式算），
   装不了才按公式自实现，并在产出里标注"自实现，与原文可能有数值差异"。
6. **移植**：只改第 4 节允许改的部分。
7. **实测顺序**：先**单维/单模块**验证有没有信号（IC、命中率、分组单调性），
   再上整体策略。**不要一上来就跑完整回测**——信号在哪一层丢的会看不出来。
8. **写档**：对照表 + 事实/判断分离 + 自检七问的答案 + 本次偏离项清单。

## 8. 本次（FinRL）的完整复盘，作为第一个样例

### 我最初错的版本
- 特征：自己手搓 12 维（5/20/60 日动量、20 日波动率、离 MA20/MA60、量比、20 日位置、RSI 代理、距高低点、当前仓位）
- 任务：单票三档择时（空仓/半仓/满仓）
- 动作：离散 3 档
- 奖励：日收益率
- 结论：RL 训练集跑输基准、换种子策略漂移、被最笨单因子打败 → **"算法层不拆"**

### 它真实的版本（读源码后）
- 特征：`finrl/config.py :: INDICATORS` = `macd / boll_ub / boll_lb / rsi_30 / cci_30 / dx_30 / close_30_sma / close_60_sma`
- 状态：`[现金] + 全部收盘价 + 全部持仓股数 + 8×N 个指标`（`env_stocktrading.py :: _initiate_state`）
- 动作：`spaces.Box(low=-1, high=1, shape=(action_space,))`，再 `actions * hmax` 取整为股数
- 奖励：`self.reward = end_total_asset - begin_total_asset`，再 `* reward_scaling`
- 执行：t 日收盘决策 → 按 t 日收盘价成交 → 估值用 t+1 价格（**T+1 无误**）
- 风控：`turbulence_threshold` 超限则全平
- 数据源：Yahoo / Alpaca / Binance / **Tushare** / WRDS / JoinQuant，含 `Asia/Shanghai` 时区

### 移植后重测（`tools/exp_finrl_indicators.py`，stockstats 原库）
300 只票、520 日训练 / 250 日样本外，归一化后逐维过三期门禁：

| 维度 | 训练期 IC | 测试期 IC | 符号 |
|---|---|---|---|
| rsi_30 | −0.0614 | −0.0756 | 同号 |
| close/SMA30−1 | −0.0611 | −0.0665 | 同号 |
| close/SMA60−1 | −0.0594 | −0.0646 | 同号 |
| boll_lb/close−1 | +0.0614 | +0.0626 | 同号 |
| macd/close | −0.0543 | −0.0615 | 同号 |
| cci_30 | −0.0538 | −0.0591 | 同号 |
| 布林%B | −0.0535 | −0.0546 | 同号 |
| boll_ub/close−1 | +0.0193 | +0.0266 | 同号（未过 IC 线）|
| dx_30 | −0.0300 | +0.0006 | **翻号** |

训练期过 6/9、测试期过 7/9、7 维符号一致。**结论从"不拆"改为"能拆，且原料层已验证有信号"。**

### 这次暴露的第四个教训（新加）
**量纲**。FinRL 把 `macd`、`boll_ub`、`close_30_sma` 的**原始值**直接喂网络，这些都是价格单位，
100 元的票与 5 元的票数值差 20 倍，**在截面上不可比**。实测：`macd` 原始值 IC −0.0482（拒），
除以收盘价后 IC −0.0543（训练期仍拒、测试期过）。做截面研究必须先归一化，
但**移植时不能因此改它的输入形式**——那是它的设计选择，改了要标"偏离"。
