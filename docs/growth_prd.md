## 1. 项目信息

- **Language**：中文
- **Programming Language**：原生 JS + 手绘 SVG（前端，不引图表库）/ Python + SQLite（后端，沿用 `server.py` 风格）；**不引入 Vite/React/MUI 等新框架**（用户显式约束）
- **Project Name**：`growth_review_panel`
- **原始需求复述**：在「复盘成长」大类（`learn`）下新增一个集中面板，让应用"看得见自己在成长、能沉淀教训、能整合外部知识"。本期（已裁剪）只做 **A 判断进化轨迹** 与 **D 校准自检** 两个只读可视化区，复用现有预测引擎表（`predictor_adjust_log` / `prediction_run` / `prediction_item` / `predictor_score`）；**不新增任何抓取逻辑**。同时预留 **E 论点验证/外部知识武器库** 与 **C 区新增外部知识武器库** 的 UI 占位 + 表结构（分类 `technical_emotion` 技术面/情绪、`macro_strategy` 宏观策略），本期不实际抓取。**重点：隔离机制**——不同外部知识源/轨道的理论互相冲突，必须独立存储、独立验证、独立开关，验证结果默认只影响该来源"可信度评分"，不直接改写 predictor 六路信号权重，UI 并排展示并标注来源，不做自动合并。

## 2. 产品定义

### 产品目标
为本地股票论坛查看器构建一个"复盘成长"集中面板，把原本散落在预测引擎、回测、知识库中的自成长能力集中、可读、可追溯地呈现出来：让王总一眼看见判断权重与命中率的自我进化轨迹、看清引擎当前的信念状态与校准逻辑，并为将来接入外部博主知识（技术面/情绪、宏观策略两类）预留隔离的接入位——确保任何来源的冲突理论都能独立验证、独立开关、互不污染，默认不干预核心信号权重。

### 用户故事
1. **As a 个人投资者（王总）**，I want 在一个面板里看到六路（十二维）信号权重随时间的变化曲线 + 每日预测 T+1/T+3/T+5 命中率轨迹，so that 我能确认引擎"确实在自我进化"、而不是凭感觉。
2. **As a 个人投资者（王总）**，I want 看到引擎当前各信号权重、最近一次调整原因、以及"今日若重跑会怎么判"的预览，so that 我能理解并信任它的判断逻辑（校准自检）。
3. **As a 个人投资者（王总）**，I want 把教训沉淀成"人话卡片" + 我的手工笔记，so that 经验不流失、下次遇到同类情形能调出来对照。
4. **As a 个人投资者（王总）**，I want 接入外部博主观点（技术面/情绪、宏观策略）时，每个来源独立开关、独立可信度评分，冲突理论并排展示并标注来源，so that 不同流派互不打架、不被自动加权平均污染我的判断。
5. **As a 个人投资者（王总）**，I want 外部知识若想"提升到信号权重"，必须我显式确认才生效，so that 外部噪声不会悄悄改写核心引擎。

## 3. 需求池

### P0（Must have｜本期必做）

| 编号 | 需求 | 说明 / 数据来源 |
|---|---|---|
| P0-1 | **growth 面板框架 + 导航接入** | 在 `app.js` 的 `NAV`（key=`learn`，显示名"复盘成长"）下新增固定子标签 `growth`（显示名如"成长总览"），与 `strategy_lab`/`buffett`/`learn_tracks` 并列；沿用全局令牌/主题；不破坏现有面板渲染。 |
| P0-2 | **A 区·判断进化轨迹（只读现有表）** | ① 信号权重随时间演化曲线：读 `predictor_adjust_log`（字段 `log_date, signal_key, weight_before, weight_after, reason`），按 `log_date` 排序还原各维度权重轨迹（含当前值来自 `predictor_score.weight`）。② 每日预测命中率轨迹：复用现有 `/api/prediction/track`（`track_payload`）——`prediction_run` + `prediction_item` 的 `hit_t1/hit_t3/hit_t5`（及 `t10`）逐日命中率。手绘 SVG 折线，窗口（T+1/T+3/T+5）可切换。 |
| P0-3 | **D 区·校准自检（只读现有表）** | ① 各信号当前权重：复用 `/api/prediction/scores`（`predictor_score`，按 `kind` 分 signal/school/strategy）。② 最近调整：读 `predictor_adjust_log` 最近 N 条（`weight_before→weight_after + reason`）。③ "今日若重跑会怎么判"预览：复用 `/api/prediction/today`（`today_payload`，当前预测/研判）+ 当前权重快照，纯只读展示，**不触发实际重跑**。 |
| P0-4 | **A/D 数据读取接口** | 现有 `track`/`scores`/`today` 三个只读 API 可直接复用；**新增 1 个只读 API**（如 `/api/growth/adjust_log`）返回 `predictor_adjust_log` 按时序的完整权重演化 + 最近调整，供 A 曲线与 D 最近调整共用。纯读、幂等、不写库。 |
| P0-5 | **隔离机制·数据模型（核心）** | 新增预留表须内建隔离维度，字段至少含：`source_key`（来源/博主主键）、`category`（`technical_emotion`｜`macro_strategy`｜内部轨道）、`track`（所属轨道，对齐 `kb_sources.yaml` 的 `group`）、`enabled`（独立开关，默认 true）、`trust_score`（该来源可信度评分，REAL）、`signal_key`（被信号化的目标信号，可空）、`promoted`（是否已"提升至信号权重"，默认 0）、`updated_at`、内容/论点 JSON 字段（占位）。**验证结果只写 `trust_score`，默认不回写 `predictor_score.weight`**；仅当 `promoted=1`（用户显式确认）才允许后续提权流程。 |
| P0-6 | **空数据安全** | 新增面板/新增预留表在为空时：UI 不报错、不崩，展示"尚无数据"占位；新增表与现有 `prediction_*` 表 **零 JOIN 解耦**（沿用项目既有隔离惯例）。 |

│                    (* = 本期占位/轻量；A、D 为本期核心只读区)                                    │
│                                                                                                │
│  ── A 判断进化轨迹（P0-2）──────────────────────────────────────────────────────────────────   │

│  ── B/C/E 占位区（P1）─────────────────────────────────────────────────────────────────────   │

切换方式：顶部 Tab 切换五个区，沿用 `app.js` 现有 `ensurePanel`/`tab` 机制；A、D 区进入即拉对应只读 API（track/scores/today/adjust_log），无数据时显示占位文案。

## 5. 待确认问题清单（Open Questions）

1. **"六路信号"口径**：引擎当前已扩到 12 维（kind 分 signal/school/strategy，见 `predictor.SIGNALS`）。A 区权重演化曲线是按"原始六路"还是"当前全部 12 维"渲染？建议全部维度、按 kind 分组，但需王总确认展示粒度。
2. **外部知识抓取归属**：E 区/外部知识武器库的实际抓取（自己抓 vs 从豆包抓）由谁实现、何时做？本期只留接口位，确认不阻塞本期。
3. **可信度评分（trust_score）阈值与算法**：评分从 0–1 还是 0–100？依据什么算（回测命中？实盘跟随？），达到多少算"高可信"、是否触发提权提示？需定口径（P1 占位，P2 才真正计算）。
4. **冲突理论 UI 默认排序规则**：多条冲突来源并排时，默认按 `trust_score` 降序？按 `source_key` 字典序？还是按更新时间？需定默认排序。
5. **"提升至信号权重"的确认交互**：P2 提权闭环的二次确认形态（弹窗/开关 + 可回滚），本期仅占位，但确认 UX 方向以免返工。
6. **A 区曲线数据不足时**：`predictor_adjust_log` 早期样本极少（贝叶斯收缩前），曲线前段可能只有 1–2 点——是否允许"样本不足不画/画虚线"？需定空窗处理。
7. **growth_notes 与 learn_tracks 关系**：人工笔记是独立表还是并入现有 KB 轨道体系？建议独立表、零耦合。
