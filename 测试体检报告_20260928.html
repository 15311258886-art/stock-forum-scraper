发现的问题（按优先级）

P0

原生窗口疑似白屏：WebView2 运行时多版本并存

桌面窗口进程和窗口句柄都创建成功，但渲染进程无主窗口句柄、窗口抓图近乎全白；同一页面用浏览器打开则完全正常。本机 WebView2 存在 153.0.4234.48 与 154.0.4258.37 两个版本目录并存，历史上还出现过「msedgewebview2 has stopped working」崩溃弹框。疑似渲染层加载异常（有 6+ 个历史 msedgewebview2 残留进程）。

证据：%LOCALAPPDATA%\Microsoft\EdgeWebView\Application 下两个版本目录；所有 msedgewebview2 进程 MainWindowHandle=0；PrintWindow 抓图全白；同一 URL 浏览器渲染正常。

建议：修复/重装 WebView2 Evergreen 运行时（仅保留最新版），清理残留进程；desktop_app 增加「加载超时自检 → 自动回退默认浏览器」。

P0

两个 viewer.server 进程并存（同命令 34088 / 45604）

当前有父子两个「python -m viewer.server」进程同时存在，虽 SO_EXCLUSIVEADDRUSE 已阻止双端口绑定（仅 34088 在监听），但残留父进程占用资源，且任何重复启动路径都可能让新旧代码进程并存，出现「改了代码不生效 / 数据跳变」。

证据：Get-CimInstance 显示 PID 45604（父）→ 34088（子），均启动于 21:59:22，命令行相同。

建议：server 进程级也加互斥/去重（如命令行启动时检测已有实例）；排查 45604 的启动来源（WorkBuddy 调度或重复双击），停掉残留父进程。

P1

资金流（moneyflow）系列无兜底，当前全部空数据

moneyflow_stock / moneyflow_rank / moneyflow_board 均返回 ok:false（东财 push2 接口不可达）。同页面 quote 已有「腾讯行情兜底」能正常出数，但资金流没有兜底，前端显示空态。

证据：/api/moneyflow_rank → "未取到资金流排行（东财 push2 接口不可达）"；/api/quote → "腾讯行情（东财 push2 不可用，已自动兜底）"。

建议：为资金流增加备用数据源（腾讯/新浪/同花顺）或超时降级提示，避免页面空白。

P1

日志丢失 + 中文乱码

server.log 最后写入 09-26 04:22（当前运行实例未落盘——pythonw 无控制台，print/logging 输出被丢弃，出问题无法排查）；auto_update.log 等文件中文全部乱码（UTF-8 内容被按 GBK 写入/读取，编码不一致）。

证据：server.log mtime=2026/9/26 4:22:46 且内容为乱码；auto_update_status.json 中中文乱码；desktop_app.py 无日志文件输出。

建议：日志统一落盘 viewer/logs/server-YYYYMMDD.log，强制 UTF-8 编码；desktop 启动路径同样生效；旧乱码日志归档。

P2

工程卫生：临时脚本与备份大量堆积

项目根目录有 200+ 个 _*.py 临时脚本、数百张 *_shot/*.png 截图、40+ 个 app.db 备份（每个 42MB）、static 目录 40+ 个 .bak 文件，累计占用数百 MB，并拖慢目录扫描与备份。

证据：根目录清单；app.db.bak.* 14 份 × 42MB；static/*.bak 40 份。

建议：临时脚本/截图归入 archive/，旧 DB 备份按日期保留最近 5 份，其余删除或压缩；.bak 统一移出 static。

P2

requirements.txt 未包含 pywebview

桌面窗口依赖 pywebview 6.2.1（venv 已装），但 requirements.txt 只有 5 个包，换机/重建环境会因缺依赖无法启动桌面版。

证据：requirements.txt 内容 vs venv pip list。

建议：补 pywebview>=6.0 到 requirements.txt，另加 logging 相关（标准库无需）。

P3

盘中无自动刷新

自动调度每天 09:00 跑一次，最新刷新停留在 18:08（5 小时前）；「实时刷新(5分钟)」需手动点击，盘中数据时效不足。

证据：/api/scheduler/status next_run 2026-09-29 09:00；refresh_status last_ok_at 18:08:40。

建议：增加盘中（09:30–15:00）可选 5–10 分钟增量刷新开关。
